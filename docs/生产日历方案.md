# 生产日历方案（待 zhao 确认，2026-10-21）

## 1. 放在哪（10-21 按 zhao 意见改：放工作台、所有人能看）

**推荐：工作台顶部加一张「生产日历」卡片 + 点开进完整页 /calendar。**

- 工作台卡片：一行显示本月、下月、下下月三个月，每月"计划产出 X 台 / 计划发货 Y 台"（本月再加"已发货 Z 台"），点某个月进完整页。卡片保持矮小，不把下面的"待办与提醒"挤下去。
- 完整页 /calendar：按月看每台的工单号、项目名、客户、台数、计划日、状态胶囊，可切"月 / 年"，按设计规范单行工具栏。菜单「我的工作」组在"工作台"下面挂一项"生产日历"。
- 不建议把整张月历塞进工作台：工作台是个人待办页，月历很长，会把每天要处理的事压到下面。
- 权限：所有人能看，不分角色。**例外点**：现在项目经理只能看本人工单，日历里会看到别人工单的工单号、项目名、客户、台数和日期。建议接受这个例外，但日历只显示这几项，不显示金额；点工单号进工单详情仍按原规则（不是自己的工单进不去详情）。
- 手机端：第一版不做。

## 2. 数据从哪来（已核对代码，main d3d5e6d）

| 需要的数 | 现有数据 | 能否直接算 |
|---|---|---|
| 数量 | QMS 同步来的工单 `quantity`（整数，每单一个数） | ✅ 能。演示数据 1 台、2 套。**未核实**：QMS 里这个数是不是"台/套"口径（可能是件数），需 zhao 确认 |
| 计划发货日 | ①QMS 工单交期 `deliveryDate`；②总计划最后一个节点"发运"的计划日（模板"交期前 0 天"） | ✅ 能 |
| 计划产出日 | 总计划节点（内置模板有"装配""调试""发运"），节点名是可改的文字，**没有字段标明哪个节点算"产出"** | ⚠️ 按名称认节点不可靠（模板可改名、可另建模板） |
| 实际发货 | "发运"节点手动标记完成日 `actualDate` | ✅ 能（前提是有人去点完成） |
| 实际产出 | 产出节点的完成日（手动标记或挂靠任务全部完成自动算） | ✅ 能，同上 |
| 分批发货 | 无。每个工单只有一个交期、一个数量 | ❌ 不支持 |

**结论：不加表就能做"计划发货"；"计划产出"需要先定口径。** 推荐做法：在总计划模板节点上加一个小标记"统计口径：产出 / 发货 / 无"（每个模板最多各一个），按模板生成总计划时带到工单节点上。这是一次小迁移（plan_template_node、plan_node 各加一列），内置"通用"模板默认把"调试"标为产出、"发运"标为发货。不用按节点名称硬匹配，避免改名后统计悄悄出错。

没发布总计划的工单：发货按 QMS 交期计入，产出不计入（灰色标"未排总计划"）。

## 3. 可选：实际对比

建议第一版就带上"计划 vs 实际"（数据已有，不额外录入）：每月计划发货 X 台、实际已发 Y 台、拖到下月 Z 台；未完成且计划日已过的显示红色胶囊。代价是依赖大家及时在总计划里点"发运完成"，否则实际数偏低。

## 4. 请 zhao 定的口径

1. **"产出"指什么节点？** 推荐"调试完成"（整机可出厂）；也可以是"装配完成"。
2. **QMS 工单数量是不是台/套？** 如果是零件数，需要在履约里另加一个"台/套数"字段由项目经理填。
3. **计划发货按哪个日期？** 推荐：有已发布总计划的按"发运"节点计划日（调整后会变），没有的按 QMS 交期。另一种是一律按 QMS 交期（合同口径，不随计划调整）。
4. **一个工单分批发货要不要支持？**（如 2 套风电模具分两个月发）推荐第一版不支持，按整单计在一个月里。
5. 是否第一版就带"实际完成 / 实际发货"对比？推荐带。
