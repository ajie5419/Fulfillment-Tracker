## 红色清单与深链

排序规则写在 `shared/board-cockpit.ts` 的 `mergeCockpitItems` 注释中：

1. 固定类别优先级：**红色工单（工单级协调）→ 超期异常（处理闭环）→ W11 停滞红线（在制停滞）**。
2. 类别内部按接口提供的天数降序；红色工单取其超期异常中最大的 `overdueDays`。无可靠时长的工单排本组末尾；同天数按稳定事项 key 升序。
3. 三类时钟不同，不跨类别直接比较天数。完整合流排序后截取 10 条；同工单的不同事项分别保留。类别优先可能使后面的类别暂不出现在前十，页头始终提供全部红色工单 / 全部超期异常 / 全部监控入口。
4. 监控 `top` 本来就按停滞天数倒序，统一 W11 阈值下红线排在黄线前；其中 RED 前十足够参与最多十条的合流，但不能作为红线总数。

| 类别 | 事项 / 责任 / 时长来源 | 深链 |
| --- | --- | --- |
| 红色工单 | `/api/overview.redWorkOrders[]` 的项目、工单号、项目经理与 `reason`（后端现有 `redReason` 原文）；时长复用 `/api/issues` 同工单最大 `overdueDays`，标“异常最长已超”，没有则标“时长未提供” | `/wo/{encodeURIComponent(工单号)}` |
| 超期异常 | `/api/issues?overdue=1&dept=0&status=UNCLOSED` 的异常编号、描述、责任部门 / 人、`overdueDays`；只取正超期 | `/risks?tab=issues&overdue=1&dept=0&id={异常ID}`，沿用风险页处理抽屉参数 |
| 停滞红线 | `/api/monitoring/status.top[]` 中 `level === RED` 的事项、工单、部门 / 责任人、`days`、状态 | 原样使用实体 `link`，即 `/parts?wo=…&part=…&step=…`（工件无 step），沿用一次性定位与准确工序高亮 |

不把 `board.stuck.days` 或 `delayDays` 的预测延期冒充已发生的逾期，不推算通用“变红多久”。未指定责任方明确标出，不把项目经理推定为工件 / 工序责任人。

## 2026-10-29 补改轮：状态胶囊与停滞红线（修正版）

施工基线 `0d656bc`。本节覆盖上文“只有四项数字 / 暂缺停滞总数”的历史结论；不实施已作废的“两行文字细分”。驾驶舱红工单仅保留工单号、产品及总计划预计拖期标题，下面显示业务状态胶囊；`redReason` 接口字段与纯函数保留，驾驶舱不再渲染该原文或工单责任底栏。看板卡片移除“卡在……自身晚……”横幅及旧标签行，保留项目经理、交期、节点圆点，使用同一个 `WoStatusCapsules` 组件（底层 `UiStatusTag`）。未建计划卡保留生成入口及业务状态胶囊。

### 胶囊词表与字段来源

以下字段均来自 `/api/board.rows[]`；`/api/overview.redWorkOrders[]` 逐字段转出同一行计数，驾驶舱不从原因文本或预警总数猜测状态。

| 胶囊 | 字段及精确来源 | 颜色 / 规则 |
| --- | --- | --- |
| 缺料 N | `shortage`：`PurchaseLine.status = OPEN` 且 `needDate <= todayDate(now)` 的采购行数，沿用看板原口径 | 红；正数展示 |
| 外购件未到 N | 新增 `purchasePending`：该工单全部 `PurchaseLine.status = OPEN` 行数，包含未到需求日的行；排除 ARRIVED / CANCELLED。展示值为 `max(0, purchasePending - shortage)`，仅表达未在缺料胶囊中出现的其余未到货行 | 红；差值为零不展示。悬停说明保留全部未到货数与已排除缺料数；不以 shortage 冒充 purchasePending |
| 设计逾期 N | `drawingOverdue`：原 `overdueWhere(todayDate(now))`；`PENDING` 且 `planDate < today`，或 `DRAWN / CUSTOMER_PENDING`、需客户确认且尚未确认、`customerPlanDate < today` | 红；正数展示 |
| 超期异常 N | `overdueIssues`：该工单未关闭异常经现有 `judgeW4` 与停工日口径判定 `overdueDays > 0` 的条数 | 红；正数展示 |
| 外协未回 N | `overdueSteps`：该工单 `RouteStep.status = OUT` 且承诺返回日按现有 `overdueDays` 已超期的工序数；未超承诺日的在外工序不计 | 红；正数展示 |
| 未齐套 N | `incompleteNodes`：现有 `incompleteWhere()` 与 `dueWindowWhere(now, thresholds.W8)` 命中的装配节点数；清单有未完成工件 / 工序或 OPEN 采购行，且需求日不晚于今天加 `max(W8.yellowDays, W8.redDays)` | 黄；窗口内未齐套为风险，不按整单颜色把所有节点改红 |
| 停滞 N 天 | 新增 `stagnationRedDays`：该工单完整 W11 监控集合中 `level = RED` 的工序 / 工件最大 `days` | 红；不存在为 null，不用 Top 或上次扫描的 Alert 推导 |
| 停滞关注 N 天 | 新增 `stagnationYellowDays`：同一完整集合中 `level = YELLOW` 的最大 `days` | 黄；仅本单无红线事项时展示，与红线胶囊互斥 |
| 未签收 N | `unsignedReleases`：该工单 `Release.status = ACTIVE` 且至少一条 `ReleaseReceipt.status = PENDING` 的发放单份数 | 黄；按份，不按未签收人数 |

红先黄后；同色按上述词表顺序。最多 **4 枚（包括 +N 本身）**：状态不超过四项时全显，超过时前三项 + 一枚 `+N`，N 等于其余真实状态项数。悬停 +N 显示其余完整状态，点击进入 `/wo/{工单号}`；看板卡本身为链接，避免嵌套链接。无命中业务状态时不额外捏造“缺料 / 停滞”等状态。

采购验收数据包含两种样本：`purchasePending = shortage = 1` 仅显示“缺料 1”；`purchasePending = 3, shortage = 2` 显示“缺料 2 / 外购件未到 1”，两枚合计为全部未到货行，避免重复计数。真库集成另覆盖 OPEN 未来需求日、ARRIVED、CANCELLED 的区分。

### 红色工单环节归属

新增 `/api/overview.redStages`，由 `shared/board-cockpit.ts:redWorkOrderStages` 对活动红色工单归一。每单只选 `stuckNode(planNodes)`（按 seq 最早的 SOURCE，排除 DONE / UPSTREAM / ON_TRACK），不累计多个卡点。先按源头节点专名，再按部门映射：

| 归属 | 源头节点映射 |
| --- | --- |
| 齐套 | 名称含“齐套” |
| 外协 | 名称含“外协”或“外包” |
| 设计 | 其余节点 dept 为 TECH / PROCESS |
| 采购 | 其余节点 dept 为 PURCHASE |
| 生产 | 其余节点 dept 为 PRODUCTION |
| 其他 | 无已发布计划、没有 SOURCE，或最早 SOURCE 不满足上述映射（如质量 / 财务 / 项目部门节点） |

数字下只列非零胶囊，顺序为设计、采购、齐套、外协、生产、其他；不再铺成句说明。每单恰好进入一组，细分和等于 `summary.red`。单测包括同一单三个源头卡点、非源头在前、关闭工单排除、无源头归其他的求和断言；浏览器样本也包含多源头节点与无计划红单。

### 停滞红线总数及下钻

`/api/monitoring/status.redCount` 对 `loadMonitoredEntities(now, thresholds.W11)` 的**完整集合**单独 reduce 统计 `level === RED`；与 Top 使用同一分级结果，但不从 Top 长度或全级别 total 取数。工序和工件各算一项，同一工件及其工序都达红线时都计入。仅在履约、未删除且未完工 / 取消工单下的非 DONE 工件及非 DONE 工序；包括待开工工序。权限保持管理总览原权限。

计时沿用 W11：工件 `Part.statusSince`；工序最近 `FlowEvent.occurredAt`，无事件回退 `startedAt`、再回退 `createdAt`。上海自然日差，含停工日，未来起点归零；`days >= redDays` 即红（含恰达边界），否则按黄线 / 正常。状态变化或新的业务活动重置起点后即按新集合回落，无需等待下一次预警扫描。

驾驶舱第五项“停滞红线”取该字段，失败或未加载显示 `—`，零值显示 `0`；点击 `/monitoring?level=RED`。监控接口增加可组合的 `level=RED|YELLOW|GREEN` 校验，页面“只看红线”开关读写 URL。红线入口默认“全部在制”，同时列工件和工序；切实体、状态和分页保留红线条件，同页深链 / 前进后退 / 刷新从 URL 反向同步。红线模式 Top 也仅展示 RED；分布统计仍保留全体在履约工单的原口径。
