## 第六轮修订：料单/工艺状态加发放前置

### 问题与规则

演示环境出现 DEMO-WO-002「模具加热系统布置图」仍在设计、图纸未发放但料单已下发，以及 DEMO-WO-001「液压系统原理图」设计完成、图纸未发放但料单编制中的组合。核实状态变更服务原来只检查状态机，没有检查发放前置；演示种子也直接写入了上述不合规则的状态。

1. 料单、工艺的开始编制和下发都要求本任务存在有效发放单。直接复用 `drawings.ts isReleased`：`Release.drawingTaskId = taskId` 且 `status = ACTIVE`；不增加签收、客户确认或设计派生状态门槛，也不把仅关联同一工件的独立发放单算成本任务已发放。
2. 未满足时服务端独立抛 `FlowError`，分别提示「图纸未发放，不能开始编制料单」「图纸未发放，不能下发料单」，工艺替换对应名称。修改、撤回等回退不加发放门槛；已取消任务仍沿用原处理。工艺原有的手动修改退回编制中也属于回退，继续允许。
3. 发放单作废后，直接关联任务的已下发料单和已下发工艺分别转 `REVISING`，各记一条日志，操作人是作废人、来源是该发放单、备注为「因发放单作废 + 单号」。编制中保持原状。即使另有有效版本，也先回退已下发文档，随后可按仍有效的发放单重新下发。
4. 第五轮 readiness 口径不变：料单 `ISSUED` 仍是第一道开工前提之一。沿用工件 → 任务 → 发放单锁顺序；回退、设计状态重算后再重评开工待办，避免按作废前状态误发。集成覆盖正式发放 → 编制 / 下发料单 → 实际开工，以及作废 / 重发后的待办恢复。

### 作废联动核实结论

原 `createRelease(type=CHANGE)` 调用 `markRevisingByChange`，仅在设计变更发出时回退已下发料单。原 `voidRelease` 处理签收、待办、预警、等变更和 `settleTask`，没有回退任何料单 / 工艺状态，也没有写对应 `ProcessDocLog`，因此本轮补 `markRevisingByVoid`；没有重复设计变更已有的联动。

原工艺枚举只有 `NONE / DRAFTING / ISSUED`，无法保存本次明确要求的工艺 `REVISING`，因此增加一个枚举值及最小 SQL 迁移，保留原值顺序；已执行 `prisma generate`。迁移通过相关集成的 `migrate deploy` 在测试库部署，未部署演示库或生产库。
