# 履约系统：角色与可见范围现状（核对 main f987c47，2026-10-19）

标注：【事实】= 代码里直接看到的；【推断】= 由代码推出、未在运行环境验证。

## 1. 角色从哪来

| 身份 | 来源 | 谁来维护 | 代码位置 |
|---|---|---|---|
| 登录用户、姓名、所在部门 | QMS 账号（统一登录），部门从 QMS 同步过来 | QMS | server/api/me.get.ts |
| 外协专员 / 部门负责人(带部门名) / 项目部负责人 / 分管领导 / 财务 | 履约系统"设置 → 通知对象"手工添加 | 管理员 | prisma/schema.prisma `NotifyRole`，server/api/settings/roles |
| 项目经理 | 设置页给每个工单指定一个人 | 管理员 | `WorkOrderExt.projectManagerId` |
| 生产经理 / 采购负责人 / 技术负责人 / 质量负责人 | 不是单独角色，= "部门负责人 + 部门名为 生产部/采购部/技术部/质量部" | 管理员 | releases/constants.ts 等 |
| 管理员 | 服务器环境变量 NUXT_ADMIN_USER_IDS | 运维改配置后重启 | server/utils/auth.ts |
| 设计负责人、节点负责人、采购负责人(到人)、工序责任人 | 各条业务记录上指定到人 | 业务操作人 | 各业务表 ownerId / buyerId |

【事实】QMS 的角色（roleName）不同步过来，履约系统不用 QMS 角色。
【事实】部门负责人按"部门名称文字"和 QMS 部门名比对；名字写得和 QMS 不一致时，该部门的预警找不到负责人（不会报错，直接跳过）。

## 2. 能看到哪些工单（唯一规则，server/utils/auth.ts `resolveScope`）

| 用户 | 能看的工单 |
|---|---|
| 管理员、上表任一通知角色（含领导、财务、外协专员、部门负责人） | 全部 |
| 不是任何工单项目经理的普通用户（一线、技术员等） | 全部 |
| 只当项目经理、没有其他角色 | 只看自己负责的工单 |

例外：出图任务的设计负责人、装配节点负责人、发放单的接收人，即使工单不在范围内也能看到发给自己的那一条。
这个范围对看板、预警列表、异常列表、采购、付款、出图、齐套、工件、手机端全部生效（后端统一拦，不是只藏按钮）。

## 3. 电脑端菜单

【事实】除"设置"（仅管理员）和"演示工具"（开了演示开关才有）外，**所有人看到的菜单完全一样**：每日（我的提醒/预警/异常/看板）、技术、采购、生产 四组。
部门负责人进异常列表时默认筛"本部门"，可以切回全部；这是默认筛选，不是限制。

## 4. 各角色能做什么（操作权限）

| 操作 | 谁能做 |
|---|---|
| 改阈值、停工日、通知对象、项目经理；维护路线模板 | 仅管理员 |
| 付款标"已付/暂缓" | 财务、管理员 |
| 删除付款申请 | 申请人、管理员 |
| 受理异常、填处理结果 | 责任人、责任部门负责人、管理员 |
| 改派异常 | 责任部门负责人、该工单项目经理、项目部负责人、管理员 |
| 确认关闭/退回异常 | 上报人、该工单项目经理、项目部负责人、管理员 |
| 标记出图/撤销 | 设计负责人本人、管理员 |
| 新建/改/删装配节点 | 生产经理、该工单项目经理、管理员 |
| 签收/拒收发放单 | 只能签发给自己的 |
| 作废发放单 | 发放人、管理员 |
| 确认变更影响 | 收到该待办的人（生产经理、外协专员）、发放人、管理员 |
| 预警转异常 | 预警责任人、该工单项目经理、管理员 |
| **其余操作**：建/改/删工件和工序、开工/完工/发出/返厂、导入 BOM、建/改/删采购行、标到货、导入采购、建出图任务、建发放单、提付款申请、上报异常 | **能看到该工单的任何登录用户** |

## 5. 提醒（"我的提醒"按人发，每人只看到发给自己的）

- 升级阶梯（scan.ts `recipientsFor`）：提醒级 → 责任人；黄 → 加责任部门负责人 + 该工单项目经理；红 → 再加项目部负责人 + 分管领导。
- 每日 07:30 汇总：发给部门负责人、项目部负责人、分管领导、各工单项目经理，内容按各自可见范围统计。
- 新的黄/红预警在电脑端右上角弹出（每分钟查一次）。

## 6. 领导看到什么

【事实】领导 = 通知角色"分管领导"。看到的是：全部工单的看板（每工单一行红黄绿、外协在途、超期、未关闭异常、未签收、缺料、出图逾期、未齐套）、所有红色预警提醒、每日汇总。没有专门给领导的页面。

## 7. 手机端（/m）

【事实】5 个页签所有人一样：提醒、在途、发出、签收、异常；数据范围同第 2 节。

## 8. 缺口与建议（未改代码，待 zhao 定）

| # | 缺口 | 影响 | 建议 |
|---|---|---|---|
| G1 | 查看基本是"人人看全部"，只有纯项目经理受限 | 一线、外协专员也能看全部付款金额 | 付款申请（金额）只给财务、采购部、项目经理、项目部负责人、领导、管理员看 |
| G2 | 大部分修改操作只要"能看到工单"就能做 | 任何人可删工件/采购行、标到货、建发放单，误操作难追责 | 按部门收紧：采购行/到货→采购部+管理员；工件工序编辑删除→生产部+外协专员+项目经理；出图任务、发放→技术部+管理员。开工/完工/发出保持宽松（现场要用） |
| G3 | 菜单人人一样 | 一线看到 15 个菜单，不知道看哪个 | 按角色默认展开相关分组、首页落到本岗位页面（只调显示，不做硬限制） |
| G4 | 领导没有汇总视图 | 领导要逐行看看板 | 加"领导总览"：红黄工单数、按部门/环节（设计、采购、外协、齐套、异常）的超期数量排行、本周新增/关闭异常 |
| G5 | 角色全靠管理员手工配，部门靠名字文字比对 | 配漏或名字写错，预警悄悄发不到人 | 设置页添加部门负责人时改为从 QMS 部门下拉选；设置页显示"哪些部门没有负责人" |
| G6 | 管理员靠环境变量 | 换管理员要改服务器配置并重启 | 试点期可接受；上线后再考虑放到设置页 |

建议优先级：G2、G1 上线前做（数据安全/误操作），G5 上线前做（否则预警会漏），G3、G4 可试点中按反馈做。
