# 日志与审计规范

本文件是项目的日志规则来源，项目 Skill 只负责导航。运行日志用于排障，业务审计用于追溯已提交的变化。

## 应用日志

通过 `server/observability/logger.ts` 的 `logEvent` 输出 Pino JSON 到 stdout。服务端不再使用 console，不序列化整个请求、响应或业务对象。

固定字段为 time（UTC ISO）、level、service、environment、event。白名单附加字段：requestId、actorId、module、taskName、method、route、statusCode、durationMs、count、entityId、resultCode；客户端报告另有 clientFingerprint、clientErrorType、relatedRequestId。新增字段先评估敏感性并补测试。

- 每次请求生成 UUID，响应返回 X-Request-Id，不信任客户端同名头。业务服务通过 AsyncLocalStorage 关联编号，后台任务建立独立上下文。
- request.completed 每请求最多一次，记录状态与耗时；request.failed 记录异常分类。请求量统计只计 completed，不能将两类事件相加。
- route 仅记录模板，未匹配记 unmatched，不记录查询参数与实际 URL。
- 4xx 使用 warn，5xx 使用 error；异常仅保留安全类型与白名单错误码。message、stack、cause 可能含 SQL 和凭据，不直接输出，依靠事件名、模块、请求和对象编号定位。
- 后台任务有 started/completed/failed。completed 表示函数返回，部分失败需结合 sync.result、scan.result 的 resultCode 和 step.failed 判断。
- 禁止记录密码、令牌、Cookie、Authorization、OAuth code/state、正文、个人备注、完整财务数据。付款金额只进入受权限保护的审计表。
- LOG_LEVEL 默认 info，支持 Pino 常用级别；生产设为 silent 将关闭运行日志。

## 业务审计

AuditLog 对应 MySQL audit_log，记录请求编号、操作人、动作、对象和受控 metadata。系统操作允许 actorId 为空；非请求调用允许 requestId 为空。

recordAudit(tx, entry) 必须使用**业务修改的同一事务**。审计失败抛出并回滚业务，禁止 catch 后继续提交或另开事务补写成功审计。新增业务功能按此规则显式接入，不自动复制整个业务对象。

审计表无业务外键，不随对象级联删除。应用只追加及管理员查询，没有修改/删除接口；这不是防数据库管理员篡改的合规存证系统。纳入数据库备份，默认不自动清理，保留期由业务确定。

| 已接入范围 | 记录内容 |
| --- | --- |
| 异常 IssueLog | 状态前后值；人工备注记录动作，不复制正文 |
| 已发布计划 PlanChangeLog | 调整种类、日期；节点删除后保留 |
| 工艺/材料 ProcessDocLog | 文件状态、发放单编号 |
| 生产 FlowEvent | 流转类型、数量、来源 |
| 付款 | 创建、改状态、删除；创建/删除时的金额 |
| 管理员设置 | 阈值、停工日、通知角色、项目经理、部门对照 |

保留原业务记录与页面，历史记录不倒填，演示造数不计正式业务操作。并非所有 CRUD 已有永久审计：草稿计划、登录及其他未接入操作不能宣称覆盖。跨 QMS 工单写回仍使用原 WorkOrderLocalSave 恢复记录，不将跨系统调用当成单库事务。

管理员查询 `GET /api/settings/audit?page=1&pageSize=20`，支持 requestId、entityType、entityId，最多每页 100 条，沿用统一 API 响应。只有管理员可访问，未新增审计业务页面。

## 采集与部署

链路为 Pino → Docker json-file → Alloy → Loki → Grafana，应用不请求 Loki。Docker non-blocking 缓冲 4MB，应用日志滚动 20MB × 5；缓冲耗尽或日志滚动可能丢失运行日志，不能替代事务审计。

使用 docker-compose.yml 与 docker-compose.observability.yml，固定版本镜像。适用于 Linux Docker 默认 /var/lib/docker/containers；rootless、自定义 data-root 或其他运行时需调整挂载。

Alloy 只读挂载日志目录，不暴露 Docker API socket。只处理标签 com.ft.log-source=fulfillment 的容器：转发 JSON service=fulfillment-tracker 的记录，其他 stderr 仅转成固定错误标记，其他 stdout 丢弃；采集进程仍可读取挂载目录的其他日志，应作为运维组件管理。

索引标签仅 service/environment/level；requestId、actorId、entityId 留在正文。Alloy 读取位置、Loki 数据和 Grafana 设置使用独立卷。发送缓冲不保证重启不丢数据；本配置不启用需要 experimental 标志的 Alloy WAL。

Loki 为单机文件存储，通过 compactor 保留 30 天，不会依据剩余磁盘自动清理。需监控磁盘容量、采集失败与长期断连；不提供高可用或零丢失保证。

Loki 不暴露主机端口；Grafana 仅绑定本机 3300，关闭匿名访问/注册，必须通过运维凭据机制提供 GRAFANA_ADMIN_PASSWORD。

```bash
docker compose -f docker-compose.yml -f docker-compose.observability.yml config --quiet
# 先按发版手册备份并执行数据库 migration，再发布新应用。
docker compose -f docker-compose.yml -f docker-compose.observability.yml up -d --build
```

以上为部署操作，需有部署授权。不要复制普通 config 输出，它可能展开环境凭据。关闭采集只停止 alloy/loki/grafana，不删除命名卷；回滚应用保留新增审计表，禁止清除历史记录。

Grafana 自动加载数据源及 Fulfillment 看板：请求量、5xx、耗时 P95、错误日志。Explore 示例：

```logql
{service="fulfillment-tracker"} | json | requestId="替换为响应请求编号"
{service="fulfillment-tracker",level="error"}
```

告警渠道为邮件，配置方式见下文；真实收件人、SMTP 凭据、Linux 主机权限和外部探测主机须在部署时落实，本地模拟投递不等于真实邮箱验收。

## 生产错误覆盖

| 层面 | 实现及行为 |
| --- | --- |
| 浏览器 | observability.client 插件接收 Vue、Nuxt、JS、未处理 Promise、资源加载错误；公共 API 请求失败即使被页面 catch，也通过统一请求层报告 |
| 接口与依赖 | 请求失败出口；Prisma error 事件；身份桥、同步、工单写回、BOM 的非成功 HTTP 与网络错误；不增加隐式重试 |
| 尽力执行的业务分支 | 凭据撤销、附件清理、同步分资源失败、工单本地恢复失败都记录；原本允许继续的业务仍继续，事务重试记录 warning |
| 后台任务 | 启动/结束时间及运行数指标；超过两分钟记录 task.overdue，但不强制取消事务；超过预期周期未运行告警 |
| Node 进程 | 生产启用 uncaughtExceptionMonitor 和置前 unhandledRejection 处理，向 stderr 同步写安全 fatal 标记，退出码 1；不让框架默认监听继续打印原始错误或维持不可靠进程 |
| 启动前异常 | Alloy 将履约容器非 JSON stderr 转成 runtime.unstructured 错误标记，不转发原始内容；异常发生在应用启动前时不能获得请求编号 |
| 容器/主机 | cAdvisor 的 OOM、重启指标；node-exporter 的磁盘/inode；黑盒健康探测；Docker restart 恢复退出进程（仅 unhealthy 不自动重启） |
| 监测系统 | Prometheus 检查组件可用性、Alloy 丢弃/重试和邮件失败；Loki 检查日志心跳；独立主机探测业务和监测健康接口 |

浏览器上报不包含原始错误文本、堆栈、URL 参数、Cookie 或表单内容；指纹用于聚合同类错误，不是堆栈回放或源码定位工具。服务端将其标记为 client.reported，不能当作可信服务端身份或执行事实。

上报入口 `/api/telemetry/client` 在未登录时也可用，要求同源 Origin、JSON、严格字段、最多 4KB 和三秒读取期限。客户端一分钟最多 20 条并去重，不重试；服务端单进程全局最多 120 条/分钟、直连来源最多 20 条/分钟。反向代理后的请求可能共享同一来源限额；默认不信任任意 X-Forwarded-For，规模扩大时在可信入口配置限流。断网、脚本未加载或触发限流时，不保证每条前端错误都能送达。

运行指标在独立端口 9464，仅设置 FT_METRICS_ENABLED=1 后开启；默认监听回环地址，Compose 内部网络设置 FT_METRICS_HOST=0.0.0.0，**不映射公网端口**。指标不包含用户、请求或对象编号。心跳每 30 秒发送。

### catch 分支处理约定

本次核对服务端 catch：API/权限/校验转换最终交给统一出口；事务失败重新抛出；Prisma 冲突与死锁已由数据库事件记录，重试另记 warning；计划预览故意回滚属于正常控制流；并发幂等命中属于正常业务结果。HTTP 失败后的响应流取消、上报自身失败允许静默结束，避免覆盖原错误或递归上报。dev 演示造数的容错不作为生产监控入口。

新增 catch 必须注明归属：重新抛出、已记录后继续、或解释正常控制流。不得无理由吞掉意外错误。质量门禁禁止服务端 console 回流；它不能自动证明每个 catch 的业务语义，仍需代码审查和故障测试。

## 邮件告警与独立主机部署

监测叠加配置新增 Prometheus、Alertmanager、黑盒探测、node-exporter、cAdvisor，Grafana 加载 Prometheus 数据源。告警覆盖服务不可用、5 分钟错误、进程/容器重启、OOM、磁盘小于 15%、inode 小于 10%、任务停跑/停滞、日志丢弃和邮件发送失败。阈值是初始运维配置，可在规则文件中调整并复测。

**cAdvisor 是高权限主机观测组件**：配置使用 privileged、宿主目录及 Docker socket 所在目录；只在受信 Linux 运维环境部署。只读挂载 socket 并不会让 Docker API 变为只读。监测网络和接口均不对外发布；不应把这份 Linux 主机挂载直接应用到个人 Mac。node-exporter 同样只读观察宿主文件系统。

由运维安全注入以下环境变量，不把值提交到 Git 或复制进对话：

- ALERT_EMAIL_FROM、ALERT_EMAIL_TO（多个收件人用逗号分隔）。
- ALERT_SMTP_ADDRESS（host:port）、ALERT_SMTP_USERNAME、ALERT_SMTP_PASSWORD。
- ALERT_PUBLIC_HEALTH_URL（生产 HTTPS `/api/health` 地址，不含凭据和查询参数）。
- 原有 GRAFANA_ADMIN_PASSWORD。

生产统一执行 [首次生产部署](首次生产部署.md) 中的 `node scripts/production.mjs deploy`，它从生产配置生成邮件文件，并校验及启动整套监测。独立监测主机仍可使用 `node scripts/render-monitoring-config.mjs` 从安全注入的环境变量生成配置。密码单独写入 0600 文件，目录 0700；强制 SMTP TLS，不将密码写入 YAML 或输出。Alertmanager 以 root 读取这些只读挂载文件。

**必须在另一台主机运行** `docker compose -f docker-compose.monitoring-external.yml -p fulfillment-external up -d`，并在该主机独立生成邮件配置。它探测 `/api/health` 和 `/api/health/monitoring`，覆盖整机断电、网络故障、反向代理失联和监测系统停止；两份配置放在同一主机不能提供这项保障。建议外部实例使用独立 SMTP 服务，避免邮件服务自身故障成为共同盲点。

监测栈本身的邮件发送失败只能在尚存活的指标/界面中看到；单一邮件渠道失效时无法保证邮件通知送达。新代码、监测配置与实际部署/收件验收必须分别报告。

## 验证

单元测试覆盖并发隔离、敏感字段过滤、错误响应编号、完成日志去重、事务失败。集成测试覆盖真实提交、回滚、删除后保留与迁移重复执行。tests/integration/audit.test.ts 会临时重命名审计表制造故障，**只允许可丢弃测试库，禁止并行或指向业务库**。

采集配置使用固定镜像执行 alloy validate、loki -verify-config，并以合成日志检查白名单过滤和 Loki 查询。配置校验不等于链路已运行，本地验证不等于生产部署。

补充验证入口：`tests/unit/client-telemetry.test.ts`、`telemetry-endpoint.test.ts`、`fatal-errors.test.ts`、`dependency-observability.test.ts`；`promtool test rules tests/observability/prometheus.test.yaml` 在测试容器中将规则目录挂载为 `/config`。SMTP sink 仅丢弃并计数模拟邮件，不能用于生产投递。子进程崩溃测试验证真实非零退出，前端事件测试使用 jsdom，不应当作真实浏览器全流程验收。

参考：[Alloy 文件采集](https://grafana.com/docs/alloy/latest/monitor/monitor-logs-from-file/)、[Loki 保留策略](https://grafana.com/docs/loki/latest/operations/storage/retention/)。
