# 演示验收到首次生产部署

生产尚未部署。演示和生产共用业务代码；本流程将验收版本部署到全新生产库，不复制演示数据、账号、附件或模拟身份桥。首次上线和后续升级共用 `scripts/production.mjs`。

## 依赖准备

- 受信 Linux Docker Engine、Compose v2、Node.js 22.16+，仓库路径 `/opt/fulfillment`。监测配置含高权限 cAdvisor，不能在个人 Mac 上启动整套主机监测。
- 真实 QMS、履约身份桥客户端凭据、精确回调白名单、首位管理员的 QMS 用户 ID；浏览器授权入口必须 HTTPS。
- MySQL 独立空库 `fulfillment`、仅访问该库的非 root 账号，具备 Prisma 迁移权限。不授予其他业务库权限。
- 已有 `qms-network`，履约容器能够访问 QMS 和数据库。异机部署须调整网络拓扑并复验。
- 正式域名及有效 HTTPS 证书，反向代理到 `127.0.0.1:3100`，保留 Host，上传上限不低于应用上限。
- SMTP 账号、告警收件人和独立监测主机。

## 唯一生产配置入口

选择演示验收通过的版本，在仓库根目录执行：

```bash
cp deploy/production.env.example deploy/production.env
chmod 600 deploy/production.env
# 安全编辑文件，替换所有 CHANGE_ME；不要将文件内容粘贴到日志或聊天。
node scripts/production.mjs check
```

Git 和镜像构建均排除填写后的文件。含 `$` 的值保留单引号；数据库用户名和密码按 URL 规则编码。`check` 只验证字段、Compose、Docker 和已有网络，不构建、不迁移、不启动容器，也不验证真实登录。

生产明确设置 `FT_DEPLOYMENT_MODE=production`，演示与沙盒使用各自模式。`NODE_ENV=production` 表示优化构建，不能替代环境隔离。生产启动拒绝演示开关、测试/演示库、root 数据库账号、缺失管理员、停用同步和无效 HTTPS 回调。

部署入口固定使用基础配置与监测叠加配置、固定项目名 `fulfillment`，避免附件卷名称漂移。不要另用 shell 的 Compose 覆盖变量改变配置。

## 首次部署与升级

```bash
node scripts/production.mjs deploy
```

执行顺序：配置预检 → 生成受限权限邮件配置 → 构建生产镜像 → 拉取监测镜像 → 校验邮件配置 → 容器内检查数据库、QMS 可达性及附件目录权限 → 保存旧应用镜像（若有）→ 迁移及状态检查 → 启动应用和监测 → 验证本机、公网 HTTPS 和监测健康接口。

独立复验：`node scripts/production.mjs verify`。接口必须返回 `{ code: 0, data: { ok: true }, message: ... }`；HTTP 200 的代理错误页不算成功。

迁移只创建或升级结构，不调用演示造数。重复执行不清除业务数据；失败时停止。升级前按上线手册备份数据库和附件。`fulfillment-tracker:prev` 仅保留旧镜像，不回滚数据库；健康失败返回非零，必须核对表结构兼容性后人工回退，不自动运行可能不兼容的旧程序。

## 空库业务初始化及正式开放清单

| 操作 | 必须确认 |
| --- | --- |
| 真实 QMS 管理员、普通账号分别登录 | 回调成功，管理员能进设置，普通账号不能越权 |
| 首次同步 | 设置页预期资源同步成功；工单、部门、用户与 QMS 一致 |
| 部门对照、负责人、通知角色、项目经理 | 缺失负责人已处理，未知部门不猜测映射，工单可见范围正确 |
| 停工日、预警阈值、总计划模板 | 使用真实业务设置，不复制 DEMO 模板；手工编制或模板生成计划可用 |
| 经批准的试点工单 | 编制/发布、接收待办、角色操作、附件上传读取和审计关联通过 |
| 后台任务 | 至少观察一次同步及规则扫描开始/结束，不能仅看进程存活 |
| 真实邮件 | 明确标注的运维测试告警及恢复邮件送达；模拟 SMTP 不能替代 |
| 独立监测主机 | 业务和监测探测正常，受控故障能从另一主机发现 |
| 备份恢复 | 恢复到独立目标核对数据库和附件，不覆盖当前业务库 |

管理员 ID 来自真实 QMS，不能使用演示 ID 猜测。生产写入、真实邮件与故障演练仅在对应部署/验收授权下执行。上述业务配置不适合在空库脚本中自动填入虚构负责人。

## 隔离演练

`node scripts/rehearse-production.mjs` 使用专用容器、随机凭据、空库和生产镜像，验证迁移重复执行、演示配置阻断、应用健康、匿名访问拦截、登录跳转和附件持久化。只连接合成身份服务，不连接真实 QMS，不发邮件。清理本次容器、卷和临时配置，保留构建镜像。macOS 使用 Apple Container 时加 `--container`；已有同版本镜像时可加 `--skip-build`。CI 的 Production image rehearsal 使用 Linux Docker 执行相同脚本。

本地演练不能证明正式 DNS、证书、SMTP、Linux 主机指标和 QMS 授权已配置完成。这些须按上表现场验收，不能以构建通过替代。

### 本次隔离验证（2026-11-12）

- Linux ARM64 生产镜像按仓库 Dockerfile 构建通过；运行的是镜像内产物，不是本机开发服务。
- 本机 Apple Container 1.0 的上下文传输出现缓慢和漏文件；本次复制受控源码快照到 BuildKit 容器内部构建相同 Dockerfile，再导入镜像，用 `--container --skip-build` 完成演练。不能将此结果写成 Apple `container build .` 已通过；日常完整演练以 Linux Docker CI 为入口。
- 随机独立容器内空库迁移、重复迁移、迁移状态检查通过；生产预检及真实应用启动均拒绝演示开关。
- 应用健康、匿名设置访问拒绝、HTTPS 身份跳转、指标输出通过。附件标记在删除并重建应用容器后保留。所有演练容器和专用卷已清理。
- 生产 Compose 合并配置通过真实 Compose CLI 校验，应用启用指标且不接收 SMTP/Grafana 凭据。服务端类型检查、相关配置测试及质量门禁通过。
- 本轮全量检查（前端快照 `13e6c13`）有独立失败：`PlanNodeRow.lateTasks` 类型错误；`plan-node-table-structure` 旧 `levelColor` 断言失败；`stale-record-actions` 测试夹具缺 `FILTER_DEBOUNCE_MS`。本次未修改这些文件，不能据此宣布整个最新分支可发布。
- 没有部署生产，没有验证真实 QMS 登录或真实邮件；新增 CI 演练工作流尚需推送后运行。
