# 第二阶段开发计划：技术、工艺、采购（v0.1，2026-10-17）

> zhao 10-17 决定：先不上线，先把采购、技术、工艺的功能做全，再统一试点。
> 本文件是开发顺序和每轮范围；每轮开工前再细化字段和页面。

## 0. 原则（沿用第一期）

- **复用第一期的"流转 + 待办 + 预警"引擎**。凡是"发给谁、谁签收、超时没动"的事，都走同一套机制，不新造流程引擎。
- 每轮交付一个能在手机或电脑上实际操作的功能，规则从简，先不做审批流。
- 不做 ERP/PLM。图纸、合同、价格的正本仍在原处，本系统只管"发没发、收没收、到没到、晚没晚"。
- 数据来源不清楚的地方先给默认做法（下文标【默认】），调研后再改。

## 2. 各轮要点

### R9 发放签收（技术、工艺共用）
- **发放单**：类型（图纸 / 设计变更 / 工艺文件）、工单、关联工件（可多选）、版本号、说明、附件（PDF/照片，可选）、发放人。
- **接收对象**：按人或"部门 + 角色"选；每个接收对象生成一条流转记录和一条签收待办。
- **签收**：手机上看内容、点签收；可拒收并写原因（例如"版本不对"）。
- **变更提醒**：设计变更关联的工件如果已在加工或在外协，额外给生产经理和外协专员发待办"确认变更影响"。
- **预警 W5**：发放后超过阈值没签收，黄→红→升级，阈值在设置页可改。
- 【默认】纸质图纸照旧下发，系统登记发放单并要求签收；附件可选，不强制上传图纸文件。

### R8 BOM 导入与工序路线模板
- 首选来源：QMS 项目 BOM 及其工序要求，导入后外协专员只补"自制/外协、哪家、谁负责"。
- 模板 = 一串工序（引用 QMS 工序）+ 每道的执行方式（自制 / 厂内外协 / 厂外外协）+ 默认工期。
- 建工件时选模板，自动生成工序链，再按需增删。
- 工艺部维护模板；工艺卡、焊接工艺等文件用 R9 发放。
- 【待调研】工艺部实际产出物和职责边界；目前按"工艺并入技术发放 + 路线模板"处理。

### R10 关键物料与付款
- 到货确认【默认】：QMS 进货检验（INCOMING）自动识别 + 采购手工确认；另支持 Excel 导入采购行。
- **采购跟踪行**：工单、物料名称/规格、数量、供应商（引用 QMS 供应商或手填）、需求日、承诺到货日、实际到货、状态、采购责任人。
- **到货签收**：仓库或使用部门手机签收（复用流转）。
- **预警 W6**：承诺到货日已过未到货；需求日前 N 天仍无承诺日。
- **付款申请**：关联采购行、金额、申请日、是否卡交期（预付款未付不发货等）、财务处理状态；列表按"离需求日最近、影响最大"排序，给项目和财务看。
- **延误原因**：到货延误时填原因类别（付款 / 供应商 / 我方需求变化 / 其他），统计时分开。
- 【默认】派单到部门（部门负责人），可指定到人。
- 【默认】只跟踪关键物料（长周期、进口、大件），由采购员手工录入；不导入全 BOM。

### R11 设计出图任务
- 出图任务：工单、部件、设计负责人、计划完成日、客户确认（需要 / 不需要，确认日）、状态。
- 完成出图后一键生成 R9 发放单。
- 预警 W7：计划完成日前未出图；客户确认超期。
- 设计负荷：按人列在手任务数和逾期数。

### R12 齐套
- 装配节点：工单下的总装 / 部装节点，带需求日。
- 节点所需清单：选工件（来自 M1）和关键物料（来自 R10）。
- 齐套率 = 已到/已完成 ÷ 应有；缺件清单按节点列出，标出各缺件当前卡在哪一步。
- 预警：节点需求日前 N 天齐套率不足。
