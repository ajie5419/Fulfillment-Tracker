# 共用分页方案

日期：2026-10-28。状态：已核对开源方案与本地依赖，设计尚未实施。

## 1. 目标与设计决定

建立项目级的共用分页能力，统一电脑表格、按工单分组、手机列表及弹窗选项的读取方式，消除固定取前 500 / 300 / 200 条造成的不可达数据。

采用三层结构：**现成组件的共用适配 + Nuxt 请求能力 + 统一接口契约**。业务服务继续负责权限、筛选、排序、统计与查询。沿用已安装的 Ant Design Vue、Vant、Nuxt 和 Prisma，本轮不新增依赖，不自行实现分页控件、滚动监听或通用请求框架。

首版统一使用页码分页，便于电脑端跳页和返回原页；手机通过同一接口逐页追加。每页条数是单次响应限制，不能再变成整张列表的总上限。跨请求读取实时数据，不承诺整次浏览具有数据库快照一致性。

### 1.1 开源复用核对与选型

核对日期为 2026-10-28。以下能力来自官方文档、官方仓库及本地已安装源码；尚未通过本项目的接入试验验证。是否新增依赖由实际缺口决定，不把“不加依赖”作为脱离成本的目标。

| 方案 | 已确认能力 | 本项目决定 |
| --- | --- | --- |
| Ant Design Vue 4.2.6，已安装 | `Pagination` 支持受控页码、每页条数、总数和翻页事件；`Table` 也有内置分页 | 直接复用 `a-pagination`，共用组件仅统一配置、文案和样式 |
| Vant 4.10.2，已安装 | `List` 提供触底加载、加载中、结束、错误和点击错误重试交互 | 直接复用 `van-list`；不重写滚动检测或加载状态 UI |
| Nuxt 3.21.11，已安装 | `useFetch` / `useAsyncData` 提供响应式参数、SSR 数据传递、请求状态、同 key 请求去重与取消，并防止被替代的同 key 请求覆盖状态 | 继续使用现有请求体系；公共适配只补分页参数、筛选重置、追加结果和路由衔接 |
| [Alova](https://alova.js.org/tutorial/client/strategy/use-pagination/) | `usePagination` 同时支持翻页、追加和相邻页预取 | 可替代通用分页请求逻辑，但需要引入另一套请求与缓存配置；本轮已有能力足够，暂不引入 |
| [Vue Request](https://www.attojs.com/api/pagination.html) | `usePagination` 管理页码请求；[useLoadMore](https://www.attojs.com/api/loadMore.html) 管理追加、错误及重试等 | 功能匹配，但与现有 Nuxt 请求状态重叠；暂不引入 |
| [TanStack Vue Query](https://tanstack.com/query/latest/docs/framework/vue/guides/infinite-queries) | `useInfiniteQuery` 管理已取页面、下一页和加载状态；官方有 [Nuxt 3 SSR 接入说明](https://tanstack.com/query/latest/docs/framework/vue/guides/ssr) | 能用；需增加 QueryClient、SSR 状态传递及失效策略，当前不为分页单独迁移请求体系 |
| [VueUse useOffsetPagination](https://vueuse.org/core/useOffsetPagination/) | 提供页码、页数、上一页 / 下一页及变化回调，请求由调用方提供 | 不能单独解决请求、追加和后端截断；不为页码计算单独引入 |
| [Prisma Pagination Extension](https://github.com/deptyped/prisma-extension-pagination) | 提供页码和游标扩展；0.7.6 声明的 peer 范围包含 Prisma 6 | 原生 Prisma 已支持 `skip` / `take`；扩展不能替代本项目的付款业务排序和权限聚合，暂不引入；声明兼容不等于本项目验证通过 |

上表后五个候选在核对时均未列入本项目直接依赖。Alova、Vue Request、TanStack Query、VueUse 和 Prisma Pagination Extension 的官方仓库均标注 MIT；许可信息与功能文档已核对，没有安装这些候选或执行兼容性测试。

选择现有栈是基于本项目已普遍使用 `useFetch`、页面风格已经固定的接入成本判断，不代表其他库不支持 Nuxt。Nuxt 的单次读取能力也不等于完整的无限列表能力：成功页面的追加、筛选切换时隔离、已选项回填仍需小范围适配，不能宣称组件自动解决。

**缩小原方案的自定义范围**：不写通用缓存、请求调度、自动重试、预取或失效引擎；不同时用 Nuxt 和另一个库管理同一列表。如果首批接入实际需要这类能力，应重新评估上述请求库，优先复用，不能继续向 `usePagedList` 堆通用机制。

## 2. 现状与影响范围

| 页面或入口 | 当前行为 | 接入要求 |
| --- | --- | --- |
| 采购电脑、手机到货 | 最多 500 条；电脑仅本地翻页，手机无继续读取 | 共用页码 / 追加模式、错误与重试 |
| 付款申请的关联物料 | 同样使用采购接口，只能搜索已加载选项 | 远程搜索、分页追加、已选项回填 |
| 付款申请列表 | 最多 500 条；截断后再次按紧急程度排序；底部合计基于返回记录 | 先完成全局排序再分页，汇总改为服务端全范围计算 |
| 电脑发放签收、手机我的签收 | 200 条；手机已处理仅最近 50 条 | 返回真实总数并提供后续页 |
| 设计、工艺、齐套 | 上限分别为 500 / 500 / 300；部分电脑页有提示，手机无继续读取 | 复用公共分页，保留业务筛选、权限和分组 |
| 齐套编辑的关键物料选项 | 每工单最多 1000 条 | 接入分页搜索选项 |
| 工作台普通提醒 | 最多 100 条；未读总数另行统计 | 提醒流可继续加载，置顶、每日汇总保持独立 |
| 总计划和工艺变更记录 | 各最多 200 条 | 独立历史记录分页 |

异常列表已通过 PR #48 消除固定截断。本轮不把它改回有限数据源；风险汇总等调用方依赖完整结果，后续若分页，须同时提供完整范围的汇总接口。全局搜索的少量快捷候选按其用途保留。

## 3. 公共层的职责

以下为拟新增文件，不代表已经存在。

| 公共能力 | 拟定位置 | 负责的内容 |
| --- | --- | --- |
| `PageResult<T>` | `shared/pagination.ts` | 数据页的公共类型、默认条数和条数上限，不依赖 Prisma |
| 分页参数校验 | `server/schemas/pagination.ts` | 页码、每页条数和偏移量合法性；供各业务查询 schema 组合 |
| `usePagedList` | `app/composables/usePagedList.ts` | 基于 Nuxt 的薄适配：统一分页参数、筛选重置、成功页追加与隔离、路由状态；直接暴露原有读取状态和刷新能力 |
| `UiListPager` | `app/components/ui/ListPager.vue` | 包装 `a-pagination`，统一电脑端配置、总数文案和事件 |
| `UiLoadMoreList` | `app/components/ui/LoadMoreList.vue` | 包装 `van-list`，通过插槽承载手机记录；绑定现成加载、错误重试和结束状态 |
| `UiPagedSelect`，第二个选料入口接入时提取 | `app/components/ui/PagedSelect.vue` | 包装现有 `a-select`，复用分页读取；不重写选择控件，业务提供搜索、标签和按 ID 回填函数 |

电脑表格和分组视图都使用同一 `UiListPager`。表格关闭内置分页（`pagination=false`），直接展示服务端本页数据，避免同一批数据再次本地切页或出现两套页码。组件接收页码、条数和总数，转发 `a-pagination` 的变化事件，不直接请求业务接口，不重新计算页码按钮。

手机使用独立的 `UiLoadMoreList` 适配现有 `van-list`，不把桌面页码和移动端滚动交互硬塞进同一组件。页面明确选用组件，不按浏览器宽度切换，以保持服务端渲染与客户端一致。初次已通过 Nuxt 读取时须协调 `immediate-check` 和加载状态，避免挂载后重复取第一页。

`usePagedList` 接收资源与筛选身份、分页参数和读取配置，通过 Nuxt 现有能力处理请求。不能在自定义组合函数内部无条件等待 `useFetch`；遵守 Nuxt 自定义封装的调用规则。电脑只替换当前页；手机仅合并同一筛选下成功的页。后续页失败保留成功页集合，不直接用失败后可能清空的 `data` 覆盖已展示记录。

页面继续提供筛选、列定义、卡片和操作。公共层不接管业务表单、金额权限、业务排序或路由路径，不自建全局数据缓存。详情返回所需的已加载页与滚动位置属于当前列表导航状态，需有明确的生命周期，不以模块级变量跨 SSR 请求或登录用户共享。

服务端公共层只复用参数与返回规范，各业务服务组织自己的数据库查询。付款的关联需求日排序、齐套的未齐套判断等仍留在原业务服务中。

## 4. 统一接口契约

请求保留各接口原有筛选条件，统一增加：

| 字段 | 规则 |
| --- | --- |
| `page` | 从 1 开始的正整数；缺省为 1；与 `pageSize` 计算的偏移量必须是安全整数 |
| `pageSize` | 正整数，最大 100；缺省 50；电脑提供 20 / 50 / 100，手机主动传 20 |

非法参数返回明确的参数错误，不悄悄忽略，也不退回旧的固定截断行为。

```ts
export interface PageResult<T> {
  rows: T[]
  total: number
  page: number
  pageSize: number
}
```

`total` 是**权限、工单、状态、关键字等当前列表条件全部生效后的匹配总数**。`rows` 只含本页。业务可以在同一响应中增加 `stats`、`groups`、操作权限等字段；不要求所有业务共享同一套统计类型。

数据库执行顺序为：权限范围 → 业务筛选 → 完整范围排序 → 分页 → 本页名称、留言数等补充信息。每种排序最后加入唯一 ID，保证数据未变时相同条件的排序稳定。不能先取固定数量，再按业务条件过滤或重新决定全局顺序。

大数量列表不以“先全部查出、在内存切页”实现分页。服务端总数、聚合、排序使用数据库查询，明细补充只处理本页，避免逐行查询。

翻页是实时读取。排序字段或记录在浏览期间变更时，内容可能移页；唯一排序键与追加去重不能提供快照保证。需要强一致导出的场景另行设计，不借此承诺本方案没有提供的能力。

## 5. 交互与数据正确性

### 5.1 表格和按工单分组

两种视图统一按“记录条数”分页，切换视图不改变页码和筛选。同一个工单允许跨页，组标题注明“本页 X 项 / 当前筛选共 Y 项”，使用户看得出还有后续数据。

组内完成度、数量按该工单在**完整筛选结果**中的记录计算，不能再用当前页的 `groupProgress(rows)` 作为全组进度。服务端只为本页出现的工单批量计算分组汇总，保留各业务对取消、作废等状态的排除规则。

顶部统计卡保留各页面已定义的统计范围。例如采购现有统计受可见工单和所选工单影响，不受列表视图和关键字影响；这与列表的 `total` 是不同含义，字段和说明必须区分。付款底部合计按其明确的完整筛选范围汇总，并继续遵守金额可见权限，不能因聚合接口暴露无权查看的金额。

### 5.2 请求、导航和错误

- 筛选、关键字或每页条数改变时回到第 1 页。电脑将页码和条数与已有查询参数一起写入地址栏，浏览器返回与前进恢复对应筛选和页码，不丢失 `wo`、`view`、`id` 等业务参数。
- 请求 key 包含资源、筛选、页码和条数。单次读取复用 Nuxt 的去重、取消和状态保护；不同 key 的请求不保证相互取消。项目额外维护的追加结果在写入前核对筛选身份，旧成功、旧错误和旧结束回调均不能覆盖新列表；不复制 Nuxt 的整套请求生命周期实现。
- 首次加载、加载成功但为空、首次失败、已有数据后加载失败分别展示。追加失败保留已有内容和未成功的目标页，点击重试仍读该页；成功后才推进页码。
- 手机按稳定 ID 去重，追加期间阻止重复加载。切换筛选清空上一条件下的列表；从详情返回列表保留已成功的页面状态与滚动位置，不把不同筛选的缓存合并。
- 删除末页最后一条后，按最新 `total` 回到最后有效页；零条时回第 1 页。越界修正重读最多一次，避免数据持续变化时循环请求。
- 后续页读取失败不能提示为“已全部加载”；错误状态的数量不显示为成功统计的 0。

### 5.3 勾选、弹窗和定位

同一筛选下翻页保留勾选 ID，表格优先使用现有 `rowSelection.preserveSelectedRowKeys`；切换工单或筛选时清理选择并明确提示。采购付款继续限制同一工单及现有可关联条数。提交前服务端重新校验记录、所属工单和权限，不把缓存中的记录状态当作最终依据。

物料选择器使用轻量分页搜索接口，返回 ID、名称、规格、状态等必要字段。搜索条件先在服务器生效，再分页。已选项独立按 ID 回填并校验可见范围和所属工单；某项不在本页，不能据此清除它。采购付款先在现有 `a-select` 上接入；齐套编辑接入时从两个实际入口提取共同适配，保留各自对取消物料等状态的规则，不先造通用选料框架。

提醒链接带 `id` 时仍通过详情接口定位；目标不在当前页也能打开。列表刷新和翻页不能把用户正在编辑的弹窗切换到另一条记录，保留 PR #47 对过期响应和操作对象的保护。

### 5.4 付款排序的专门处理

付款按“未付在前 → 卡交期在前 → 最近未到货物料需求日在前 → 申请日 → 建立时间 → 唯一 ID”在完整权限及筛选范围内决定顺序，再选本页 ID、读取明细。

最近需求日需要从关联物料聚合得到，不能先按建立时间读 500 条再计算。若现有 Prisma 查询不足以表达，使用项目已有的参数化 SQL 方式实现这一业务查询；排序、数量、合计使用相同权限与筛选范围。

## 6. 接入顺序与兼容方式

共用能力随首个真实业务接入交付，每个 PR 都应能独立验证和合并。

| PR | 内容 | 完成标准 |
| --- | --- | --- |
| 1 | 公共类型、参数校验、Nuxt 分页适配、`a-pagination` / `van-list` 共用包装；采购电脑、手机、现有付款选料弹窗接入 | 采购全部现有调用方适配；第 501 条可通过后续页或远程搜索访问；统计与分组正确；无新增请求框架或自建控件 |
| 2 | 付款申请接入 | 全局紧急排序、真实总数、完整范围合计和金额权限正确 |
| 3 | 发放签收、手机我的签收接入 | 待签收不被 200 条截断；已处理记录可继续读取 |
| 4 | 设计、工艺、齐套及齐套物料选择器接入；提取两个选料入口的共用适配 | 桌面和手机复用公共能力，消除各固定总量上限；采购付款与齐套保留各自业务规则 |
| 5 | 工作台提醒及变更记录接入 | 普通提醒 / 历史记录能继续加载；置顶、每日汇总与未读总数保持各自口径 |

每次接口返回结构变更必须同批更新其所有调用方、共享类型和相关测试。原来返回数组的接口改为数据页时，不能只改其中一个页面。无需引入通用的“新旧返回结构自动猜测”逻辑。

计划变更记录可拆出独立分页读取入口，避免每次翻历史都重读整个总计划。提醒的普通列表使用数据页，置顶、汇总和未读数作为独立业务元数据返回；分页参数不能影响它们的统计。

各批接入完成后再更新该页面设计规范与使用说明。全程保留当前用户未提交的其他文件变更；本方案不包含数据库结构迁移和部署配置变更。

## 7. 验收与退出条件

### 公共能力

- 0、1、恰好一页、多一条、501、1001 条，以及相同排序值的数据，覆盖全页后既不重复也不遗漏。
- 非法页码、非法条数、条数超过上限、安全整数检查和删除后越界，行为明确。
- 首次失败、后续页失败、重试成功、连续点击、快速切筛及请求乱序，均不能产生旧数据覆盖、新筛选混入旧记录或假空列表。
- 表格 / 分组切换、浏览器前进后退、详情返回、跨页勾选和已选项回填均有用例。
- 测试聚焦本项目的参数衔接、成功页追加、筛选隔离与业务行为，不重复测试开源组件内部的页码算法和滚动检测。

### 业务正确性

- 权限、工单、状态、搜索在分页前生效；任何一页和任何聚合均不能泄露跨范围数据。
- 采购统计卡、分组汇总、付款金额合计按已定义的完整范围计算，不随每页条数变化。
- 付款的第 501 条如果最紧急，应出现在正确的前页，不能因建立时间较旧而漏掉。
- 选择器能搜到原先 500 / 1000 条之外的合法物料，已选对象在翻页后仍可见且可正确提交。

### 执行检查

- 公共状态与参数做单元测试；数据库筛选、排序、分页和聚合用独立 MySQL 测试库验证。
- 每批代码运行相关测试、类型检查和生产构建；采购首批分别在 1440 电脑端和 390 手机端做运行验证，覆盖翻页、错误重试、分组和选料。
- 未配置独立测试库导致跳过时，明确记录为未验证。源码、模拟接口、浏览器交互和真实数据库的结果分别报告。
- 启动前端服务沿用会话中有效的授权范围；使用已有运行环境时仍区分代码版本。构建成功不能替代运行验证。
