# 独立演示环境

此启动方式使用本机 Apple Container 中的 `qms-container-mysql`（MySQL 映射端口 3307），单独创建 `fulfillment_demo` 数据库和仅可访问该库的同名账号。不会清空或迁移原来的数据库，不加载项目 `.env`。

先执行 `pnpm build`，再执行 `node scripts/demo.mjs --check` 检查构建产物、证书和端口，最后执行 `pnpm demo` 启动。需要已有 `certs/localhost.pem` 与配套私钥，证书应覆盖 `127.0.0.1`。

- 演示入口：`https://127.0.0.1:3101`。使用不同于原环境 `localhost` 的主机名，避免两套环境的登录 Cookie 相互覆盖。
- 模拟身份桥：`http://127.0.0.1:4101`，只在本机监听，不连接真实 QMS，不提供同步资源。
- 初始数据：3 个 `DEMO-` 工单及设计、采购、生产、齐套、总计划等演示记录。原来的 113 个工单及试编计划不进入此库。
- 登录时选择岗位；“演示管理员 / 分管领导”（u-005）有管理员权限。换角色使用页面上的退出 / 切换账号入口。
- 附件单独存放于 `.data/demo/uploads`。数据库连接和身份桥凭据每次启动随机生成，仅在进程内使用。
- 重启保留试用进度。恢复初始演示数据时，在演示入口的“演示工具”先清除演示数据，再写入演示数据；此操作只针对独立演示库。
- 清除时保留演示登录账号，避免清空后无法登录、无法重新写入数据。
- 停止运行脚本即可停止应用与模拟身份桥，数据库保留。不要同时启动两份脚本。

在“项目总览”点击“新建工单”，工单号使用 `DEMO-` 前缀（例如 `DEMO-WO-004`），选择演示客户、填写数量和交期。保存后可编制项目计划；工单详情支持修改和取消。新建、修改、取消仅写入独立演示库，不连接真实 QMS，仍按项目部或管理员权限控制。新建工单也纳入演示数据清理范围。

模拟身份桥只承担角色登录。不要将此入口作为正式业务环境使用。
# 合同生效日期

总计划在草稿阶段不计算执行延期或上游延期传播，总计划表不显示“预计／完成”列；过去的计划日期仅提示发布前核对。发布后才按当前日期与实际执行情况预测。此规则由生产和演示共用。

总计划概览显示工单号和 QMS 的 `effectiveTime`（合同生效日期）；缺失时显示“—”。上线需先部署 QMS 同步字段，执行履约数据库迁移，再重拉历史工单以补齐该字段。

更新已有演示环境时使用 `pnpm demo --keep-data`，迁移数据库并保留当前数据，不重新写入演示样例。
