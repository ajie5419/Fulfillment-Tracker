# 采购计划下发（轻量版）验收记录

分支：`feat/purchase-plan`；基线：`ce8acbe`（全流程修复第四轮）。

## 功能与状态机

- 入口 `/purchase-plans`，详情 `/purchase-plans/:id`。技术部、采购部、项目经理、管理员通过现有菜单分区可见；其他角色通过链接按工单可见范围只读。
- 技术部、管理员新建计划头和明细，支持编辑、删除未转入的明细、排序、下发、撤回。不做审批、供应商比价、库存。
- `DRAFT → ISSUED → WITHDRAWN → ISSUED`。草稿、撤回状态可编辑，已下发锁定。撤回沿用原计划，不复制；最近下发人、下发时间保留，再下发时更新。
- 已转采购行的明细始终不能编辑或删除。撤回不撤销采购行，也不清除回链；未转入的明细可修改后再下发。
- 下发给 `notify_role` 中采购部 `DEPT_HEAD` 发 `PURCHASE_PLAN_ISSUED` 待办，`refType=purchasePlan`。未设置负责人时提示未通知，不伪报通知成功。撤回取消未处理待办；全部明细转入后关闭待办。
- 待办支持桌面/手机工作台查看入口，遵循工单范围；此类待办不开放转交。

## 权限

后端集中于 `server/services/auth/permissions.ts`，接口同时检查操作权限和工单可见范围，前端按钮只是展示层。

| 操作 | 技术部 | 采购部 | 项目经理 | 管理员 |
| --- | --- | --- | --- | --- |
| 新建、编辑、增删明细、下发、撤回 | 是 | 否 | 否 | 是 |
| 转采购行 | 否 | 是 | 否 | 是 |
| 只读 | 工单范围内 | 工单范围内 | 所负责工单 | 全部 |

## 转采购行与完成度

- 逐行、整单转入均调用既有 `createLine`，仅增加可传入现有事务的方式。保留工件、供应商、采购负责人、节点校验及“可以开工”待办副作用。
- 映射：物料名/规格/数量/单位/需求日/工件/备注照明细；供应商作为手填名称，不匹配 QMS 供应商；节点取计划头，采购负责人及创建人取当前操作人。
- 每行事务内锁工件、锁计划头，创建采购行后写 `convertedLineId`。任一步失败整行回滚；整单逐行处理，汇总成功数及逐行错误。唯一回链与串行化防止并发重复转入。
- 转入的采购行只能取消，不能删除，以保留计划执行记录。
- `shared/purchase-plans.ts` 的 `purchasePlanProgress` 是列表、详情共用的唯一计算入口。
- 分母 `y` 为计划全部明细数；已转入 `x` 为非空回链数；已到货 `a` 为关联采购行状态 `ARRIVED` 的明细数。取消仍算已转入，不算已到货；撤销到货后实时减少到货数。数量不作为权重；空计划为 0/0，不计算百分比。
- 计划头更换节点只影响以后转入的明细；已转采购行保留其执行信息。

## 总计划与迁移

手工新建、修改复用 `resolvePlanNode`：只能挂同工单节点；已发布总计划的新建必须选节点；已挂节点不能直接清空。类别是自由文本，不强绑节点。下发前再次按采购行新建口径检查节点。

迁移：`20261105090000_purchase_plan`（晚于 `20261104090000`）。增加计划头、明细表、状态/来源字段、唯一回链及相关外键索引；工件/节点删除置空，采购行回链采用 Restrict 保留执行记录。

## BOM 带出规则与草稿字段口径

现有解析未提供需求日，无图号行的空/非法数量会变成 0。草稿允许日期暂空、保留解析数量，技术部补齐后才可下发；不猜日期、不把 0 自动改为 1。草稿需求日字段可空、数量可为 0，下发时统一要求正数和有效需求日。

- 只带出 classifyBom 结果中的 noDrawing 行，继续沿用 isFastener 排除螺栓、螺母等辅材。每次正式应用创建一张 BOM_AUTO 草稿；标题带发放单号（直接服务应用无单号时带日期）。
- 数量沿用解析结果；不合并无图号行，不修改多列数量识别策略；没有数量列沿用解析器默认 1，非法/空值沿用 0，技术部需核对。规格、单位、供应商没有可靠来源时留空供手工填写。
- 无 noDrawing 行不建采购计划；预览接口不落库。落库与正式发放、建工件共用同一事务，后续附件绑定、校验等失败时整单回滚。
- 同一 BOM 分批或再次正式发放按每次应用创建新草稿（不根据名称推断重复采购需求）；请技术部核对后下发。
- ReleaseCreateModal 仅在接口返回 purchasePlanItems 时提示“另有 n 项外购件已生成采购计划草稿”。

## PR #53 审查修复

- 发现：Codex 审查 P2 指出，计划明细全部转入后，撤回、修改标题或备注再下发仍会给采购部负责人新增 `OPEN` 执行待办；此时没有可转明细，待办无法通过转入完成。
- 改法：`changePurchasePlanStatus` 下发时仅在存在 `convertedLineId === null` 的明细时查询负责人并创建 `PURCHASE_PLAN_ISSUED` 待办。全部已转入时不建待办，返回 `notified: 0`，仍正常更新下发状态、操作人和时间。原有空明细禁止下发、数量/日期及节点校验保持不变。

- 回归：新增“两行全部转入 → 撤回 → 改标题 → 再下发”集成用例，断言 `notified: 0`、原待办记录保持不变、没有 `OPEN` 执行待办，且采购部负责人 `listMyTodos` 列表不含该计划。修复前该用例实测失败（再次下发 `notified: 1`），修复后通过；首次下发建待办、最后一行转入后关闭的原有用例继续通过。

## 日期手打修复

日期：2026-10-29；分支：`fix/fullflow-findings-20261029`；基线：`6e3d186`。

### 复现与根因

- 使用 `@vue/test-utils` + jsdom，保留真实 `a-modal`、`a-date-picker`、弹窗 Teleport、日历面板、中文 ConfigProvider 和 dayjs 中文 locale。采购计划详情、PurchaseEditModal、DrawingEditModal 编译并挂载真实 SFC 的 script 和 template，沿用既有 `tests/helpers/vue-script.ts` 的编译/自动导入隔离方式，只替代接口、Nuxt 自动导入与无关子组件；绑定仍为 reactive 字段，日期初始为 undefined，使用 `value-format="YYYY-MM-DD"`。
- 修复前六个指定字段逐个失败：输入 `2026-11-05` 后直接点击保存，模型为 undefined；其余十二个日期声明逐个以相同真实弹窗和 reactive 绑定挂载，输入同一日期后保存仍为原值 `2026-11-01`。保存动作依次派发 mousedown、等待 Vue 微任务、切换焦点产生 blur，再 click，避免直接调用保存函数绕过真实事件顺序。
- 对照实验：原始选择器单独 blur 和 Enter 均能更新模型，日历点选也能更新。因此不是 reactive、初始 undefined 或 value-format 字符串序列化失效。
- 根因已由已安装的 ant-design-vue **4.2.6 源码和组件实测共同确认**：`vc-picker/Picker.js` 的输入解析只更新内部 `selectedValue`，尚未调用 `triggerChange`。`vc-picker/hooks/usePickerInput.js` 注册的全局 mousedown 在点保存按钮时先 `triggerOpen(false)`；`Picker.js` 的关闭 watcher 把输入文本和 `selectedValue` 恢复成旧 `mergedValue`，open watcher 也重置输入变化标记。随后 blur 的提交分支要求 `open.value` 为 true，此时跳过提交，弹窗保存得到 null 或旧日期。

### 改法与非法输入口径

- 新增 `app/components/ui/DatePicker.vue`，统一使用 `YYYY-MM-DD` 展示和字符串模型，在 openChange(false) 的同步回调内、Ant 恢复文本之前校验并提交合法手打值。日历点选/清空优先使用 Ant 的 change，避免旧输入覆盖刚选中的日期。
- 选择“**非法/残缺输入恢复为原值并关闭面板**”这一口径，不增加新的表单提示样式，也不改变本页允许草稿需求日为空、下发前必填的校验。严格解析拒绝不存在的日期、非补零格式、其他分隔符、尾随文本和残缺日期；手动删空同样恢复原值，需要清空时使用原有清空按钮。原值为空则恢复空值。
- 阻止同一次 blur/Enter 提交此前输入过程中遗留的合法片段；Escape 放弃输入；继续尊重 disabled-date、allow-clear、placeholder 和原有样式。空值以 null 向内部组件传递以保持受控，局部适配 Ant 类型声明遗漏 null 的问题。
- 没有 value-format 的 PlanEditor 等 dayjs 对象选择器未改动；RouteEditDrawer 的日期字段不属于 a-modal 模式，本轮未改动、未宣称验收通过。
