# 履约新建工单：QMS ↔ 履约接口约定（v1，2026-10-27，zhao 已确认方案）

方案文档：https://claude.ai/artifact/PfzmNkc47Dtoja8SAtD2Qn

## 认证与格式
- 全部挂在 QMS `/api/integration/fulfillment/` 下，认证与现有同步接口完全相同：请求头 `X-Identity-Client-Id` / `X-Identity-Client-Secret`（身份桥客户端凭据）。
- 成功：HTTP 200，`{ code: 0, data }`。失败：HTTP 400（参数错/客户或事业部无效/操作人无效）、404（工单不存在或已删除）、409（工单号已存在 `WORK_ORDER_EXISTS`，或版本冲突 `OPTIMISTIC_LOCK_CONFLICT`），body 带中文 `message`，履约直接显示给用户。
- 每个写请求带 `actorUserId`（QMS 用户 ID，两边相同）；QMS 校验用户存在且未删除，审计日志记这个人。

## 工单对象（写接口返回 data、同步接口 items 都用这个形状）
```
{ workOrderNumber, customerName, customerNameId, projectName|null, division|null, divisionId|null,
  quantity, deliveryDate(ISO), status: OPEN|IN_PROGRESS|COMPLETED|CANCELLED,
  version, isDeleted, updatedAt(ISO 带毫秒) }
```
现有 `GET work-orders` 同步接口增加输出 `customerNameId`、`division`、`divisionId`、`version`（只加字段，旧客户端不受影响）。

## 1. 新建  POST /api/integration/fulfillment/work-orders
body: `{ workOrderNumber, customerNameId, projectName?, divisionId?, quantity(>=1), deliveryDate('YYYY-MM-DD'), actorUserId }`
- 工单号 trim 后非空、≤64；名称由 QMS 按 ID 回填（客户=字典 customer_name，事业部=departments）。
- 复用 QMS 现有建单逻辑：查重（未删除已存在 → 409 WORK_ORDER_EXISTS）、软删除过的同号恢复、审计。status 固定 OPEN，multiStationEnabled=false，effectiveTime 空。

## 2. 修改  PUT /api/integration/fulfillment/work-orders/:workOrderNumber
body: `{ version, actorUserId, customerNameId?, projectName?, divisionId?, quantity?, deliveryDate?, status?(OPEN|IN_PROGRESS|COMPLETED) }`
- **不允许改工单号**（body 里出现 workOrderNumber 且不同 → 400）。CANCELLED 的工单不能改（400）。走 QMS 现有乐观锁（version 不符 → 409）。返回更新后的工单对象。

## 3. 取消  POST /api/integration/fulfillment/work-orders/:workOrderNumber/cancel
body: `{ version, actorUserId }` → status=CANCELLED，乐观锁同上，返回工单对象。已取消再取消 → 直接返回当前对象（幂等）。不提供删除。

## 4. 客户列表  GET /api/integration/fulfillment/customers
→ `data: [{ id, name }]`，字典 customer_name 中启用、未删除的，按名称排序。只读。

## QMS 侧其他改动
- QMS 工单页：隐藏新建、编辑、导入、删除、批量删除按钮，只留查看/导出，并在页面上提示“工单由履约系统维护”。
- 对应 QMS 原接口（work-order index.post / index.put / import.post / index.delete / batch-delete.post）返回 403“工单由履约系统维护，请到履约系统操作”。工单要求(requirements)等子功能不动。
- 上线：QMS 先发版，紧接着履约发版。
