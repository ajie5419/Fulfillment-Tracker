# 项目部总计划（R14）设计 v0.1（2026-10-19）

zhao 已选：总计划在系统里按模板建（不导入 MS Project）。本文写清做法和几处默认取舍，开发按这个来；有要改的直接说。

## 1. 总计划是什么

- 每个工单一份总计划，由 10–20 个**节点**组成，例如：合同评审、设计出图、客户确认、关键物料到货、下料组焊、机加、外协、涂装、装配、调试、发运。
- 每个节点有：名称、**责任部门**（技术/采购/生产/质量/项目部）、**计划完成日**、顺序。
- 节点按顺序排成一条主线，最后一个节点（一般是"发运"）对应工单交期。

## 2. 怎么建

1. 项目经理（或项目部、管理员）在"总计划"页给工单点"按模板生成"。
2. 模板里写的是"交期前多少天"，系统按 QMS 工单交期**倒推**出各节点日期。项目经理再按实际情况改日期、增删节点。
3. 模板在设置页维护，由项目部负责人或管理员维护。先内置一个"通用"模板，可以再建"高铁架设设备""特种车辆""风电模具"等。

## 3. 发布与基线

- 项目经理点"**发布**"后，当时的日期记为**基线**（不再变）。
- 发布后，各节点的责任部门负责人会收到一条"确认总计划节点"待办，可以确认，也可以退回并写原因。退回会提醒项目经理。
- 发布后再改计划日期，必须写**调整原因**。系统保留每次调整的记录，所以基线、当前计划、调整历史都看得到。
- 默认取舍：发布后立即生效，**不等**各部门全部确认（避免卡住）；未确认的节点在页面上标出，超过 1 天没确认的走 W5 同样的提醒升级。

## 4. 部门计划挂到节点

现有功能各加一个"所属总计划节点"选项：

| 部门计划 | 挂在哪 | 用哪个日期比 |
|---|---|---|
| 出图任务 | 设计出图类节点 | 计划完成日 |
| 采购行（关键物料） | 物料到货类节点 | 需求日（有承诺日时看承诺日） |
| 工序（自制/外协） | 组焊、机加、外协、涂装等节点 | 要求完成日（外协看承诺返回日） |
| 装配节点（齐套） | 装配类节点 | 需求日 |

- 工单已发布总计划时，新建这些记录**必须选**节点，日期默认取节点日期；以前建的老数据可以不挂（页面提示"未挂节点 N 条"）。
- 部门日期**晚于**节点日期时：可以保存，但要醒目提示，并且在总计划页标红。默认取舍：只提示不拦截，因为现场常有合理例外；拦截以后可以加。

## 5. 预计完成与交期影响（主线的作用）

- **节点预计完成日** = 取以下几项里最晚的一个：
  - 节点自己的计划日；
  - 挂在它下面的部门任务里最晚的预计日期（已完成的取实际日期；没完成、已超期的按"今天"算）；
  - 前一个节点延误后**顺延**的日期（保持原来的间隔）。
- 所以任何一个部门任务晚了，会沿主线往后推，最后一个节点的预计日期就是**预计交期**。它跟 QMS 交期比，就知道会不会拖期、拖几天。
- 节点完成：挂在下面的任务全部完成时自动完成，也可以由责任部门或项目经理手动点完成。

## 6. 预警 W9（总计划节点延误）

- **黄**：节点预计完成日晚于计划日。
- **红**：晚了 3 天及以上（阈值可在设置页改），或者预计交期晚于 QMS 交期。
- 通知对象沿用现有升级阶梯：
  - 黄：发给节点责任部门负责人和项目经理；
  - 红：再加项目部负责人和分管领导。

## 7. 在哪里看

- **新页面"总计划"**（菜单"每日"组，所有人可见）：选工单后显示节点列表，每个节点一行，列出：
  - 基线、当前计划、预计、实际日期；
  - 挂了几条部门任务、其中几条超期；
  - 点开节点能看到下面的任务，并跳到对应页面。

  页面顶部显示预计交期，以及比交期早还是晚几天。
- **看板**：每个工单增加"预计交期"和"拖期天数"两列。
- **领导总览**：增加"预计拖期工单"清单，以及"按部门统计延误节点数"。
- **每日汇总**：增加"总计划延误节点 N 个"。

## 8. 谁能做什么（沿用 R13 的角色）

| 操作 | 谁能做 |
|---|---|
| 建/改/发布总计划、调整日期 | 该工单项目经理、项目部（含项目部负责人）、管理员 |
| 确认/退回节点 | 该节点责任部门负责人 |
| 手动标记节点完成 | 该节点责任部门的人、该工单项目经理、管理员 |
| 维护模板 | 项目部负责人、管理员 |
| 查看 | 所有能看到该工单的人 |

## 9. 不做（这一轮）

- 车间周计划不在本轮做。

## 10. 排期（推断）

一轮开发（R14），完成后合并。对推进计划的影响：
- 10-30 确定试点工单不受影响；
- 试点工单需要先在系统里建好总计划；
- 11-20 上线前的测试时间会被压缩，具体看开发完成时间。
