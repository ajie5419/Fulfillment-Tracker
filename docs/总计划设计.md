zhao 已选：总计划在系统里按模板建（不导入 MS Project）。本文写清做法和几处默认取舍，开发按这个来；有要改的直接说。

## 2026-11-09：调整计划日期时联动后续节点

- 编辑节点的开始或完成日期，保存前先显示日期变化清单；确认后在同一事务内保存，取消预览不写入数据。
- 沿现有前置关系逐级计算：后续节点最早从前置完成的次日开始，多前置取最晚日期。按自然日保留工期，先消化原有空档，只顺延排不开的节点；前置提前不会自动提前后续计划。
- 未填开始日的节点按单日里程碑处理，仍保留开始日为空；已完成的后续节点不移动，预览中列出。父节点按子节点汇总，再向后传递；父节点自己的前置关系仍不隐式传给子节点。
- 发布后开始日或完成日变更均需原因；开始、完成日期分别记调整记录，受影响的非汇总节点重新请责任部门接收。部门内任务日期保持原安排，由部门重新协调。
- 预览后若计划或执行情况变化，拒绝旧预览并要求重新预览。前置、顺序、上级关系的修改需先单独保存，再调整日期。
- 演示、生产使用同一业务代码；上线需部署对应版本。

## 1. 总计划是什么

### 部门分解与指派（2026-11-09）

部门接收节点后，通过唯一的“分解任务”入口创建任务。技术部默认选择设计任务，填写名称、责任人、计划开始日（可选）和计划完成日后，创建并挂靠同一条设计任务；部门计划、设计任务列表和责任人工作台共同展示该记录。开始日不得晚于完成日。

尚无任务时入口显示“分解任务”；已有任务时显示“追加任务”，用于同一节点下继续安排其他工作。空任务列表隐藏时，分解表单仍可从节点操作入口打开。

设计任务页以所属节点、任务名称、责任人、计划起止、设计状态和操作为主；节点编号与总计划层级一致。状态标签显示当前工单与负责人范围的数量，上方只保留逾期、本周到期提醒。本周按周一至周日统计。实际完成日、客户确认、发放记录和关联工件在展开详情中查看，设计状态不混入料单或工艺状态。登记设计完成仍限任务责任人或管理员操作。

设计任务编辑按任务与责任人、计划起止、客户确认要求、所属节点、备注排列，节点下拉使用同一层级编号。设计阶段不选择生产工件；设计完成发放图纸时附 BOM，系统创建或匹配工件并关联回设计任务。已有工件关联保留，普通编辑不提交或清空该关系。客户确认定义为设计成果确认，计划早于设计完成计划时提示调整日期；登记实际确认前必须完成设计，实际确认日期不得早于实际设计完成日期。登记可填写确认说明，撤销确认或撤销设计完成时一并清空。列表分行展示设计及发放进度、具体设计预警原因、客户确认状态；已确认日期持续展示，未确认显示计划日、日期未定或逾期天数。不要求确认的任务仅在详情注明，不增加列表噪声。取消或恢复任务在列表独立确认，普通保存不改变取消状态；取消会停止预警、退出节点完成统计并解除该任务对关联工件的开工限制。

会议、资料整理等辅助工作可在表单里选择“其他任务”，仍走普通部门任务流程。已有其他任务不自动转换。采购、生产的专项分解入口也收进类型选择，继续使用各自原有业务表单。

工作台按当前设计负责人和“设计中”状态直接读取待办；改派后移交给新负责人，设计完成或取消后移除，撤销完成后恢复。设计任务的转交通过修改设计负责人完成，避免只转交待办造成责任人不一致。

- 每个工单一份总计划，由 10–20 个**节点**组成，例如：合同评审、设计出图、客户确认、关键物料到货、下料组焊、机加、外协、涂装、装配、调试、发运。
- 每个节点有：名称、**责任部门**（技术/采购/生产/质量/项目部）、**计划完成日**、顺序。
- 节点按顺序排成一条主线，最后一个节点（一般是"发运"）对应工单交期。

## 2. 怎么建

1. 项目经理（或项目部、管理员）在"总计划"页给工单点"按模板生成"。
2. 模板里写的是"交期前多少天"，系统按 QMS 工单交期**倒推**出各节点日期。项目经理再按实际情况改日期、增删节点。
3. 模板在设置页维护，由项目部负责人或管理员维护。先内置一个"通用"模板，可以再建"高铁架设设备""特种车辆""风电模具"等。

## 3. 发布与基线

- 项目经理点"**发布**"后，当时的日期记为**基线**（不再变）。
- 发布后，各节点的责任部门负责人会收到一条"确认总计划节点"待办，可以确认，也可以退回并写原因。退回会提醒项目经理。
- 发布后再改计划日期，必须写**调整原因**。系统保留每次调整的记录，所以基线、当前计划、调整历史都看得到。
- 默认取舍：发布后立即生效，**不等**各部门全部确认（避免卡住）；未确认的节点在页面上标出，超过 1 天没确认的走 W5 同样的提醒升级。

## 4. 部门计划挂到节点

现有功能各加一个"所属总计划节点"选项：

| 部门计划 | 挂在哪 | 用哪个日期比 |
|---|---|---|
| 出图任务 | 设计出图类节点 | 计划完成日 |
| 采购行（关键物料） | 物料到货类节点 | 需求日（有承诺日时看承诺日） |
| 工序（自制/外协） | 组焊、机加、外协、涂装等节点 | 要求完成日（外协看承诺返回日） |
| 装配节点（齐套） | 装配类节点 | 需求日 |

- 工单已发布总计划时，新建这些记录**必须选**节点，日期默认取节点日期；以前建的老数据可以不挂（页面提示"未挂节点 N 条"）。
- 部门日期**晚于**节点日期时：可以保存，但要醒目提示，并且在总计划页标红。默认取舍：只提示不拦截，因为现场常有合理例外；拦截以后可以加。

## 5. 预计完成与交期影响（主线的作用）

- **节点预计完成日** = 取以下几项里最晚的一个：
  - 节点自己的计划日；
  - 挂在它下面的部门任务里最晚的预计日期（已完成的取实际日期；没完成、已超期的按"今天"算）；
  - 前一个节点延误后**顺延**的日期（保持原来的间隔）。
- 所以任何一个部门任务晚了，会沿主线往后推，最后一个节点的预计日期就是**预计交期**。它跟 QMS 交期比，就知道会不会拖期、拖几天。
- 节点完成：所有有效挂靠任务和子节点完成后自动完成，完成日取最晚完成日。撤销完成或新增未完成任务后自动恢复执行中；已取消任务不计入，全部取消或没有任务不自动完成。已有分解内容的节点不提供手动完成入口，历史手动完成记录也不覆盖下级状态；仅没有任务、没有子节点的直接执行节点可以手动完成。

## 6. 预警 W9（总计划节点延误）

- **黄**：节点预计完成日晚于计划日。
- **红**：晚了 3 天及以上（阈值可在设置页改），或者预计交期晚于 QMS 交期。
- 通知对象沿用现有升级阶梯：
  - 黄：发给节点责任部门负责人和项目经理；
  - 红：再加项目部负责人和分管领导。

## 7. 在哪里看

- **新页面"总计划"**（菜单"每日"组，所有人可见）：选工单后显示节点列表，每个节点一行，列出：
  - 基线、当前计划、预计、实际日期；
  - 挂了几条部门任务、其中几条超期；
  - 点开节点能看到下面的任务，并跳到对应页面。

  页面顶部显示预计交期，以及比交期早还是晚几天。
- **看板**：每个工单增加"预计交期"和"拖期天数"两列。
- **领导总览**：增加"预计拖期工单"清单，以及"按部门统计延误节点数"。
- **每日汇总**：增加"总计划延误节点 N 个"。

## 8. 谁能做什么（沿用 R13 的角色）

| 操作 | 谁能做 |
|---|---|
| 建/改/发布总计划、调整日期 | 该工单项目经理、项目部（含项目部负责人）、管理员 |
| 确认/退回节点 | 该节点责任部门负责人 |
| 手动标记节点完成 | 该节点责任部门的人、该工单项目经理、管理员 |
| 维护模板 | 项目部负责人、管理员 |
| 查看 | 所有能看到该工单的人 |

## 10. 排期（推断）

一轮开发（R14），完成后合并。对推进计划的影响：
- 10-30 确定试点工单不受影响；
- 试点工单需要先在系统里建好总计划；
- 11-20 上线前的测试时间会被压缩，具体看开发完成时间。

发放弹窗按“发放内容、生产明细（BOM）、接收范围”组织。从设计任务进入时仅提供图纸和设计变更；工艺文件由对应入口发放。BOM 可选，上传或粘贴后沿用服务端预览，发放时创建或匹配工件；补发可补充关联已有工件。人员、部门、角色在同一选择框组合选择，服务端复用正式发放规则预览去重后的签收人数，预览失败需重试后再发放。部门和角色选择是范围合并，不是交集；按组展开排除发放人，直接指定本人仍沿用原规则。预览不产生发放单或待办，正式发放会重新校验。

设计任务工具栏分层：标题旁切换“任务 / 人员负荷”；任务页统一提供工单、负责人、关键词和一键清除筛选，右侧用视图下拉切换“工单分组 / 阶段看板 / 明细表”。设计任务视图偏好通过独立 cookie 记忆，明确的 URL 参数优先，浏览器前进后退同步恢复视图。阶段看板不重复展示状态标签栏，统计卡或链接带来的筛选以可清除提示呈现；切入看板时移除不受看板支持的“已取消”筛选。人员负荷仅显示实际支持的工单筛选。“补充任务”为次要操作，主流程仍由部门计划分解、指派任务。

工艺分流：所属总计划节点名称包含“采购计划”的技术任务（原材料、主要/其他外购件、电器件、液压件等采购计划编制），以及所属节点名称为“调试”的任务，不进入工艺列表与统计，不允许编制/下发料单或工艺，也不触发设计变更、发放单作废的工艺回退提醒。当前依据已有节点名称识别，集中维护该规则，不根据“减速机”等部件名称推断；“调试”按完整名称匹配，避免排除“调试图纸”“调试工装设计”等图纸任务。普通图纸、技术协议及未挂节点的独立设计任务仍按原流程处理。排除的任务仍保留原有技术侧进度与发放、采购或调试侧业务；若关联生产工件，不再因其未下发料单阻挡开工，原有物料到货及设计完成条件仍有效。已有任务与新任务使用同一规则，不删除历史记录。
