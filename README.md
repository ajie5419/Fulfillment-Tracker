# 项目履约系统（Fulfillment Tracker）

外协交接闭环：外协返厂报检（QMS）→ 下工序待办 → 停滞预警 → 异常升级。
设计依据：项目文件 `履约流程/系统方案设计.md`、`履约流程/技术选型与MVP范围.md`。

技术栈：Nuxt 3（Nitro 服务端）+ Prisma 6 + MySQL 8；电脑端 Ant Design Vue，手机端（`/m`）Vant。Node 22，pnpm。

## 本地启动

```bash
pnpm install
cp .env.example .env                          # 按注释填写
docker compose -f docker-compose.local.yml up -d   # 本地 MySQL；或复用 QMS 本地 MySQL，见下
pnpm db:migrate                               # 建表
pnpm cert:local                               # mkcert 生成 https://localhost 证书（身份桥只接受 https 回调）
pnpm dev                                      # https://localhost:3100
```

复用 QMS 本地 MySQL 容器时，以 root 执行一次 `docker/mysql-init.sql`，`.env` 的端口按容器实际映射填写（例如 3307）：

```bash
container exec -i <QMS MySQL 容器名> sh -c 'MYSQL_PWD="$MYSQL_ROOT_PASSWORD" mysql -uroot' < docker/mysql-init.sql
```

登录走 QMS 身份桥（接口见 `server/services/auth/identity-bridge.ts` 顶部注释，依据 QMS `apps/backend/modules/identity-bridge`）。QMS 本地还没跑起来时，可以先用模拟身份桥：

```bash
node scripts/mock-identity-bridge.mjs         # 监听 4100，授权页上选择以哪个演示用户（u-001 ~ u-006，R9 加了 u-008 测试设计员，R10 加了 u-009 测试采购员、u-010 测试财务，R11 加了 u-011 测试技术负责人，R13 加了 u-012 测试焊工、u-013 测试检验员、u-014 测试行政）登录，也可带 ?as=u-003；同一端口还有模拟的 QMS 同步接口
# .env 中改为：
# NUXT_QMS_API_BASE="http://localhost:4100"
# NUXT_QMS_AUTHORIZE_URL="http://localhost:4100/identity/authorize"
# NUXT_QMS_CLIENT_SECRET="local-dev-secret-local-dev-secret-0"
```

### 账号状态与会话撤权（2026-10-28）

- 登录除了 QMS 身份桥核验，还要求账号已同步到履约、未删除且为 `ACTIVE`。尚未同步时返回 503 并提示等待用户同步成功；已停用或已删除时返回 403，不签发新会话。
- 每次受保护请求复核本地用户状态；账号缺失、停用或删除时撤销该账号所有设备的会话，接口返回 401，页面跳转登录，并清除失效 Cookie。恢复账号后需要重新登录，旧令牌不会恢复。
- 用户同步在写入停用、删除状态的同一事务内撤销所有会话；登录创建会话与用户同步按账号行锁串行，续期遇到已撤销的会话按未登录处理。
- 撤权依据用户同步副本：正常每 5 分钟同步，QMS 状态变更在下一次成功的用户同步后生效；同步失败或关闭时不能承诺该时效。首次本地演示也须先开启模拟 QMS 同步，完成用户同步后才能登录；已有副本后才可关闭同步。

## QMS 数据同步（R2）

`sync-qms` 每 5 分钟按游标（`sync_cursor`）增量拉取 QMS 的工单、外协单位、厂内外协班组（`teams`，与外协单位同存 `qms_supplier`，kind = TEAM）、工序、部门、用户、报检，写入 `qms_*` 只读副本，然后对新报检做返厂匹配（只看工件登记之后提交的报检；多工单报检任一工单命中即候选）、QMS 不合格转异常（`inspectionResult = FAIL` 或关联了 QMS 问题单）。接口契约：`GET /api/integration/fulfillment/<resource>`，认证用身份桥同一组客户端凭据（`server/services/sync/client.ts` 顶部注释）。

- 每页写入与推进游标在同一事务里，中断后下一轮续跑，不重复、不丢；单次运行每类最多 200 页
- 某类失败记在 `sync_cursor.lastError`、连续失败次数 +1；连续 3 次给管理员发一条置顶的"我的提醒"（同一轮故障只发一次）
- 看板显示"QMS 最后同步"（各类资源里最旧的那类），有报错时显示错误；设置页"QMS 同步状态"列出每类的游标、最近错误、连续失败次数
- `NUXT_QMS_SYNC_ENABLED=0`，或 QMS 地址、客户端凭据为空时任务跳过不报错
- 本地联调：`node scripts/mock-identity-bridge.mjs` 同时提供同步接口，数据来自 `scripts/fixtures/mock-qms.json`（可用 `MOCK_QMS_FIXTURE` 换文件）；演示工具页"立即同步一次"可手动触发

## BOM 导入与路线模板（R8）

- **从 QMS BOM 导入**（生产管理页）：服务端实时调 QMS `GET /api/integration/fulfillment/work-orders/<工单号>/bom`（复用 `NUXT_QMS_API_BASE` 与客户端凭据，不受 `NUXT_QMS_SYNC_ENABLED` 影响；浏览器不直连 QMS），勾选后整批一个事务导入：每个 BOM 行建一个工件（名称、图号、数量、QMS 零件 ID → 报检按它匹配），必经工序按顺序建步骤，方式默认"自制"、不带负责人，页面标"待补充"。
- 重复导入按 BOM 行 ID（`part.qmsBomId`，同工单唯一）跳过，绝不修改已有工件；QMS 里没有工序 ID、或履约工序副本里还没有的工序跳过并提示（步骤只存工序 ID）。需要 QMS 先升级出 BOM 接口，否则提示"QMS 还没有 BOM 接口"。
- **路线模板**（设置 → 工序路线模板；原菜单"路线模板"已并入设置）：工序 + 方式 + 默认外协厂 + 默认工期；管理员维护，可从工件"另存为模板"。没有工序的工件可"套用模板"（复制步骤，负责人默认操作人；填了开工日才按默认工期推算要求完成日）。改模板不影响已套用的工件。
- 演示：写入演示数据后，`DEMO-WO-002` 的 BOM 导入读演示 BOM（不连 QMS），另带一个演示模板；清除演示数据一并删掉（含引用演示工序的模板）。本地模拟 QMS（`scripts/mock-identity-bridge.mjs`）的 `QMS-WO-2026-001` 也有 BOM。

## 发放签收 + 设计变更通知（R9）

- **发放单**（菜单"发放签收"）：类型（图纸 / 设计变更 / 工艺文件）、工单、关联工件（可多选）、版本号、说明、附件（PDF/照片，可选，每个 ≤ 20MB）。纸质图纸照旧下发，系统登记发给谁并要求签收；能看到该工单的人都能发，不审批。编号 `FF-YYMMDD-NNN`。
- **接收人**：按人选，或按"部门 + 角色"选（只选部门 = 该部门全部在职人员；角色同设置页"通知对象"），发放时展开成人（不含发放人自己）。每人一条签收记录 + 一条"签收"待办（不能转交）。
- **签收**：手机端"签收"标签页或电脑端发放单详情；可拒收并写原因，拒收会给发放人一条黄色提醒。接收人即使看不到该工单（项目经理只看自己的工单）也能看、能签发给自己的发放单和附件。发放人或管理员可作废（未签收的一并作废）。
- **设计变更**：关联工件有工序在加工或在外协时，给生产经理（生产部负责人）和外协专员发"确认变更影响"待办（都没配置时给发放人），一人确认即可；还没开工的工序标"等变更"，W2/W3 不计时，确认后解除（W2 从解除时刻重新计时）。没有在加工的工序时不发确认待办，接收人全部签收后自动解除。
- **W5 发放未签收**：从发放起计时（不含停工日），默认 4 小时提醒接收人、1 天黄（加接收人所在部门负责人、工单项目经理、发放人）、2 天红（再加项目部负责人、分管领导），不转异常；阈值在设置页改。"确认变更影响"待办没人处理时同样按 W5 计时升级（从发出确认待办起算，责任人是待确认的人，黄色起加发放人）；没有确认待办但有人拒收、"等变更"解除不了时，由发放人负责（确认或作废）。这样"等变更"不会无声挂着。看板加"未签收发放"列，每日汇总标题有未签收份数（有才显示）。

## 关键物料到货 + 付款（R10）

- **采购到货**（菜单"采购到货"）：只跟踪关键物料（长周期、进口、大件），手工登记或 Excel 批量导入。一行 = 工单、用于工件（可空）、物料名称、规格、数量 + 单位、供应商（选 QMS 供应商存 ID，也可手填名称）、需求日、承诺到货日、实际到货日、采购负责人（不选 = 采购部负责人）、延误原因。能看到该工单的人都能登记、修改、确认到货，不审批。
- **Excel 导入**：页面下载模板（`exceljs` 生成，第二张表是填写说明），逐行校验（必填、工单存在且可见、日期、数量、采购负责人按账号或姓名、工件按图号或名称、供应商名称与 QMS 一致时自动关联、文件内及与已有行重复）；有任何一行不对整批不导入并列出 Excel 行号。最多 500 行、2MB。
- **到货确认**：
  - 自动：QMS 进货检验（`category = INCOMING`，或没有分类且工序名为"进货检验"）提交后，按 **工单 + 物料名称（去空格、全半角、大小写归一）**，两边都有供应商 ID 时还要一致，且报检不早于采购行登记日，找未到货、未被报检确认过的采购行；**恰好一条**才自动确认到货（到货日 = 报检提交日，来源"QMS 报检"），多条或没有都不动、只记录不重试，留给手工确认。检验结论和数量不看（到了就算到货，不合格走异常）。每条报检只处理一次；进货检验不再进入外协返厂的"待确认匹配"。
  - 手工：电脑端"确认到货"，或手机端首页"到货确认"（采购员、仓库、使用部门都能点）。到货日默认今天、不能晚于今天；晚于需求日或承诺日时选延误原因（付款 / 供应商 / 我方需求变化 / 其他）。可撤销。
- **W6 关键物料未到**：① 有承诺日：超过承诺日（不含停工日）默认 1 天黄（采购负责人、采购部负责人、工单项目经理；有卡交期且未付的付款申请时加财务）、3 天或需求日已过红（再加项目部负责人、分管领导）；承诺日晚于需求日、需求日已过时同样红；② 没有承诺日：离需求日 ≤ 7 天黄，需求日已过红。不转异常；到货或取消后消除。阈值在设置页改。
- **付款申请**（菜单"付款申请"）：关联同一工单的一到多条采购行、金额、申请日、是否卡交期、说明。排序：未付在前 → 卡交期 → 关联物料里最近的需求日 → 申请日。财务（设置页"通知对象"里的"财务"）或管理员直接标 已付 / 暂缓 / 待付并写一句处理意见，不审批；申请人或管理员可删除未付的。延误原因选"付款"的单独统计，与"管理原因"（供应商 / 我方需求变化 / 其他）分开。
- **可以开工**：工件挂的关键物料（不算已取消的）全部到货时，给第一道工序负责人发"可以开工"待办（没有负责人发生产部负责人；第一道已开工不发）；该工序发出 / 开工后关闭；又挂上未到货的物料时没处理的待办作废。
- 看板加"缺料"列（未到货且已到需求日），每日汇总标题有缺料项数（有才显示）。演示数据含 5 条采购行（超承诺日 + 卡交期付款、无承诺日、待到货、延误到货、已到货）和 3 张付款申请；演示工具里可模拟 QMS 进货检验。

## 设计任务（R11）

- **设计任务**（菜单"设计任务"）：按部件拆。字段：工单、关联工件（可多选，也可以不关联只写部件名称）、部件名称、设计负责人（不选 = 技术部负责人，即设置页"部门负责人"里部门为"技术部"的人）、计划完成日、是否需要客户确认 + 客户确认计划日 / 实际日、备注。技术部、管理员（能看到该工单）可以新建、编辑、取消；**标记设计完成只能设计负责人本人或管理员**（负责人本人不受工单可见范围限制）。
- **状态**由事实推出：设计中 → 设计完成（图纸还没发放）→ 待客户确认（已发放、需要客户确认还没确认）→ 已完成；另有已取消。客户确认是独立节点，可以在发放前或发放后录；可撤销设计完成（未发放时）、撤销客户确认。
- **一键发放**：设计完成的任务点"一键发放"，打开 R9 新建发放单并预填类型（图纸）、工单、关联工件、说明，发放单记下 `drawingTaskId`。发放单作废后任务回到"设计完成"。
- **可以开工门槛**：工件挂着未完成（未取消）的设计任务时不发"可以开工"；全部完成（设计完成、关联发放单不是作废、需要时客户已确认）且关键物料也齐了，才给第一道工序发。只挂设计任务、没有关键物料的工件，设计完成并发放（需要时客户已确认）后也会发。沿用 R10 的 READ COMMITTED 和"先锁工件、再锁行"的顺序。
- **W7 设计逾期**：计划完成日前 2 天（含当天）仍未完成设计 → 黄；已过计划完成日 → 红（超期天数不含停工日，与 W6 一致）；设计完成、需要客户确认的，超客户确认计划日 1 天黄、4 天红。黄：设计负责人 + 技术部负责人 + 工单项目经理；红再加项目部负责人、分管领导。不转异常；阈值在设置页改（提醒列 = 计划完成日前几天，黄 / 红 = 客户确认超期天数）。
- **设计负荷**（设计任务页的页签）：按设计负责人列在手、设计中、逾期、本周到期、待客户确认。手机端首页"我的设计任务"：设计负责人看自己的任务、点"标记设计完成"；从 W7 提醒点进来（`/m/drawings?id=…`）时顶部单独显示提醒的那条任务，被升级通知的技术部负责人、项目经理等也能看到（按能否看到该工单判权限）。
- 看板加"设计逾期"列，每日汇总标题有设计逾期数（有才显示）。演示数据含 4 个设计任务（逾期红、即将到期黄、客户确认超期、不预警）和 u-011 测试技术负责人。

## 齐套（R12）

- **装配节点**（菜单"齐套"）：挂在工单下的总装 / 部装节点。字段：节点名称、需求日、负责人（不选 = 生产经理，即设置页"部门负责人"里部门为"生产部"的人）、备注、排序。**新建、编辑、删除只限生产经理、该工单项目经理、管理员**；能看到该工单的人都能看，节点负责人本人不受工单可见范围限制（只读）。
- **节点清单**：每个节点选需要的工件（多选）和关键物料（R10 采购行，只能选同一工单的）；同一工件 / 物料可以挂在多个节点上。删除节点只删节点和清单，工件、物料本身不动。
- **齐套率** = 已就绪项 ÷ 应有项（向下取整，差一项不会显示 100%）：工件状态为"完成"且没有未完成工序才算就绪；关键物料"已到货"算就绪；已取消的物料不计入应有项。清单为空的节点没有齐套率、不算未齐套、不预警。
- **不合格与完成状态**：任一工序被 QMS 不合格阻塞时，同一事务内撤销工件完成状态。最后一道先完工、其他工序仍未完成时也不算工件完成；所有工序都完成后才恢复。工序链增加、删除、复制或套用模板后也重新判定，空工序链不算完成。一个步骤关联多条异常时，仍须全部关闭才恢复该步骤；恢复齐套时记录新的完成日期。齐套列表、缺件、计数及 W8 查询同时检查工序状态，已有的"工件完成但工序有异常"记录也不会继续显示齐套；本次不批量改写历史数据。
- **缺件清单**：每个节点列出没就绪的项，并给一个"卡在哪"的主要原因。工件：当前工序（第一道未完成的）在制 / 外协中 / 有异常时照实写；还没开工时依次看 等变更 → 图纸未完成（挂着未完成的设计任务）→ 待料（挂着未到货的关键物料）→ 待开工；没有工序为"未排工序"。物料：未到货，显示承诺日、需求日，超承诺日或需求日标"逾期"，承诺日晚于节点需求日标"赶不上节点需求日"。
- **页面**：选了工单 → 节点卡片（齐套率进度条 + 缺件表）；不选工单 → 跨工单视图，按需求日从近到远，默认"只看未齐套"，展开看缺件。手机端首页"齐套 / 缺件"（只读）："我负责的"（没指定负责人的节点归生产经理）和"全部未齐套"；从 W8 提醒点进来（`/m/kitting?id=…`）顶部单独显示那个节点。
- **W8 装配节点未齐套**：需求日前 5 天内（含）仍未齐套 → 黄；前 1 天、当天或已过 → 红（按上海日历的自然日，与 W7 的"计划完成日前几天"一致，不扣停工日）。负责人（没指定 = 生产经理）收到；黄起加生产经理、工单项目经理；红再加项目部负责人、分管领导。不转异常；齐套（100%）后下一轮扫描自动消除，编辑节点改了需求日、删除节点立即消除。阈值在设置页改（黄 / 红 = 需求日前几天，黄不能小于红）。
- 看板加"未齐套节点"列（未齐套且已进入 W8 黄色窗口的节点，点进去是该工单的未齐套节点），每日汇总标题有未齐套节点数（有才显示）。演示数据含 3 个装配节点：回转机构部装（已齐套）、主梁总装（3 天后需求、缺件，W8 黄）、支腿部装（20 天后需求、缺件、不预警），并多一个已完成的演示工件"回转底座"。
- 演示数据里的日期全部在写入时按上海日历的"今天"推算（以前是模块加载时按 UTC 算，凌晨 0–8 点会差一天）；仍是"没有才写入"，已有的演示数据不改。

## 角色与权限（R13）

- **角色固定 8 种**（管理员、领导、项目部负责人、项目经理、部门负责人、外协专员、财务、部门员工），规则写在 `server/services/auth/permissions.ts`，不做可配置的权限矩阵；一个人多个角色时取并集。工单可见范围（`resolveScope`）不变。
- **部门员工**自动确定：QMS 所属部门经设置页"部门对照"换成 6 个业务部门（技术部 / 采购部 / 生产部 / 质量部 / 财务部 / 项目部）；没对照的部门沿上级找最近有对照的；都没有时按 QMS 部门名称本身（名称正好叫"生产部"等的照常生效）。换算集中在 `server/services/auth/departments.ts`，预警升级的"责任部门负责人"、异常责任部门负责人、"本部门"筛选都用它。
- **操作收紧（后端拦，403 + 中文提示）**：设计任务编辑、客户确认、建发放单 → 技术部、管理员；采购行增删改、Excel 导入、手工到货 / 撤销、提付款申请 → 采购部、该工单项目经理、管理员；工件和工序增删改、调顺序、导入 BOM、套模板 / 复制路线、处理待确认匹配 → 生产部、外协专员、该工单项目经理、管理员；开工 / 完工 / 发出 / 补登返厂 → 生产部、外协专员、该工序责任人、管理员。QMS 同步、报检自动匹配 / 自动到货、自动转序等后台流程不受影响。
- **付款金额**只给财务、采购部、领导、项目部负责人、管理员、该工单项目经理；其他人接口里金额为 null，页面显示"—"。
- **菜单**按角色显示（页面本身不拦，从提醒链接点进去可只读查看）；手机端"发出"页签只给生产部、外协专员、管理员。"领导总览"已并入"项目总览"（`/board`）：领导、项目部负责人、管理员在汇总下方多看到"卡在哪个环节"和异常统计；旧地址 `/overview` 跳到项目总览。
- 设置页"通知对象"改名"人员与角色"，部门负责人的部门改为从 6 个业务部门里选；新增"部门对照"页签，并提示哪些业务部门还没有负责人。演示数据加了部门对照和 3 个演示用户：u-012 测试焊工（组焊班 → 生产部）、u-013 测试检验员（检验科 → 质量部）、u-014 测试行政（其他部门）。

### 待办转交权限（2026-10-28）

- 只有待办当前负责人能转交，管理员不能代转他人的待办；签收待办不能转交。
- 接收人必须在 QMS 用户副本中存在、未删除且状态为 `ACTIVE`，并按现有规则有权查看待办所属工单；不能靠转交扩大工单可见范围。管理员接收人的范围按服务端管理员配置计算。
- 工序和开工待办的原负责人也必须仍能看到工单；发放单、计划节点和部门任务保留现有“本人收到的任务可处理”规则。
- 关联对象不存在或类型不支持时拒绝转交。所有校验在同一事务内完成后，才更新原待办、创建新待办；部门任务负责人随转交同步更新。

## 页面切换与操作对象（2026-10-28）

- 采购、设计编辑弹窗在保持打开时切换记录，会重新装载对应表单；新建时切换工单或总计划节点也会更新预填。旧保存请求的提示、关闭回调不会作用到后来打开的记录。
- 手机发出登记切换工单、工件或工序时清空原承诺返回日、随件发料和选择面板；清空工件同时清空工序和供应商。提交前核对工单、工件与待发出的厂外外协工序仍对应。
- 发放详情切换或关闭后，旧请求的结果、错误和加载状态不再覆盖当前记录；拒收、确认变更的输入一并清空，旧作废确认框不能继续提交。手动打开或关闭采购、设计弹窗后，先前的提醒定位请求也不会重新打开旧记录。
- 回归测试：`rtk vitest run tests/unit/stale-record-actions.test.ts`，运行真实 Vue 组件脚本及响应式生命周期，接口使用模拟结果；不等同于浏览器或数据库验收。

## 发版与部署（与 QMS 同机）

发版走 GitHub Actions：PR 标题校验 → CI → squash 合并 → release-please 开发布 PR → 合并后打 `fulfillment-v*` tag → deploy workflow SSH 到 ECS 执行 `scripts/deploy-remote.sh`（构建 → 迁移 → 启动 → 健康检查，失败自动回退 `prev` 镜像）。commit 和 PR 标题用 Conventional Commits（`feat(plan): ...`），完整规则和一次性仓库设置见 [docs/发版手册.md](docs/发版手册.md)。

首次上线（QMS 先发版、建库、IP 证书与 443 入口、环境变量、清演示数据、备份、真机验证，每步含确认与回滚）见 [docs/上线手册.md](docs/上线手册.md)。没配 Secrets 时可以手工部署：

```bash
docker compose build
docker compose run --rm fulfillment prisma migrate deploy   # 必须在启动前执行
docker compose up -d
```

容器加入 QMS 的 `qms-network`，经 `http://qms-backend:3000` 调用身份桥；端口只绑 `127.0.0.1:3100`，由 443 入口（IP 证书）反向代理。

## 环境变量

| 变量 | 说明 |
|---|---|
| `DATABASE_URL` | 履约库连接串。生产账号只授予 `fulfillment` 库权限 |
| `NUXT_QMS_API_BASE` | QMS 后端地址（服务端调用）。生产 `http://qms-backend:3000` |
| `NUXT_QMS_AUTHORIZE_URL` | QMS 授权页完整地址（浏览器跳转）。本地 `http://localhost:5666/identity/authorize`，生产 `http://<IP>/#/identity/authorize` |
| `NUXT_QMS_CLIENT_ID` / `NUXT_QMS_CLIENT_SECRET` | 与 QMS 的 `QMS_IDENTITY_CLIENT_ID` / `QMS_IDENTITY_CLIENT_SECRET` 一致，密钥 ≥32 位 |
| `NUXT_QMS_CALLBACK_URL` | 回调地址，必须 https、不带 `?` `#`，与 QMS 的 `QMS_IDENTITY_CALLBACK` 完全一致 |
| `DEV_HTTPS_KEY` / `DEV_HTTPS_CERT` | 仅本地开发：mkcert 证书路径 |
| `NUXT_DEV_TOOLS` | 仅本地开发：`1` 开启演示数据和模拟报检，默认关闭 |
| `NUXT_QMS_SYNC_ENABLED` | QMS 数据同步开关，默认开启；`0` 关闭（复用 `NUXT_QMS_API_BASE` 与客户端凭据） |
| `NUXT_ADMIN_USER_IDS` | 管理员（设置页：阈值、停工日、通知对象、工单项目经理），逗号分隔的 QMS 用户 ID；演示时用 `u-001` |

QMS 同步 `sync-qms` 每 5 分钟（`server/tasks/sync-qms.ts`）、预警扫描 `scan-rules` 每 15 分钟由 Nitro scheduledTasks 执行（`server/tasks/scan-rules.ts`），`pnpm dev` 和构建产物都会跑；用 `job_lock` 表上的租约锁防重叠（进程崩溃后租约到期自动失效：扫描 10 分钟、同步 15 分钟）。

缺少必填项时服务启动即报错退出。
